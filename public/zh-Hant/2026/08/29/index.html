Claude Code 2.1.251 把模型切換與遠端子任務納入控制面

發生了什麼：Claude Code 2.1.251 新增可阻斷、確認或標註模型切換的前後置鉤子，並在恢復會話時提供快取陳舊度與重建成本；前臺子 Agent 的工具呼叫可實時傳給 Remote Control。版本同時修復授權後替換符號連結逃逸、外掛路徑穿越等安全問題。

為什麼值得關注：模型切換、遠端觀察與許可權校驗開始共享同一執行控制面，減少長會話在切換和恢復時的盲區。

試試看

在測試倉庫為模型切換加確認鉤子，再恢復一個過期快取會話，檢查提示、成本估算、遠端事件與許可權日誌。

注意點

鉤子能阻斷切換，不等於替代沙箱與倉庫許可權；Remote Control 也會擴大會話可見範圍，應先限定裝置和觀察者。

為什麼值得關注：編碼 Agent 的基本單位正從單輪終端變成可命名、可恢復、可歸檔並與程式碼審查狀態聯動的任務集合。

注意點

八任務上限只適用於當前 Channels 設計；持久會話仍會積累上下文、檔案與許可權狀態，不能把歸檔當成安全清除。

Microsoft Agent Framework 1.16 固化後臺等待與檢查點邊界

為什麼值得關注：後臺任務、遙測、會話續傳和檢查點不可變性被放進同一框架版本，直接影響故障定位與恢復可信度。

注意點

框架修復的是介面和狀態邊界，不自動保證外部工具冪等、儲存事務或跨服務一致恢復；仍需故障注入。

06Mistral llm-d Router歐洲 / 全球推理設施2026-08-26 釋出 / 2026-08-29 觀察官方倉庫更新GitHub Stars 2許可證 Apache-2.0

Mistral 路由器開始按資料並行 Rank 命中 KV 快取

發生了什麼：Mistral 在公開 llm-d Router 分支加入資料並行感知的 KV 事件索引與字首評分，使同一 Pod 內各 Rank 的快取不再被錯誤合併；排程器可把請求固定到命中快取的 Rank，並清除客戶端傳入的 Rank 頭，避免外部繞過快取感知放置。

為什麼值得關注：共享埠的資料並行推理若只按 Pod 路由，會把看似命中的字首送到錯誤 Rank，重新計算並放大首 token 延遲。

適合誰看：執行 vLLM、SGLang、llm-d 或大規模字首快取推理叢集的基礎設施團隊。

試試看

在測試叢集構造兩個 Rank 持有不同字首塊的場景，對比更新前後的命中 Rank、重算 token、首 token 延遲和請求頭。

注意點

該能力位於 Mistral 公開分支且處理器仍標為 Alpha、預設不啟用；精確字首生產器和正確外掛配置缺一不可。

07Deep Agents全球 / 開源開發者2026-08-28 釋出 / 2026-08-29 觀察官方開源釋出GitHub Stars 28,662許可證 MIT

Deep Agents 0.7.11 為 SDK 接入 Rubric 評分鉤子

發生了什麼：LangChain 的 Deep Agents 0.7.11 新增 SDK 整合鉤子，讓外部 rubric grader 能進入 Agent 執行後的評測鏈。這個小版本沒有擴大模型或工具表面，而是提供一個明確接點，把任務結果交給按標準項執行的評分器。

為什麼值得關注：Agent 評測需要從離線指令碼進入可複用 SDK 生命週期，才能把任務標準、執行證據和迴歸結果穩定關聯。

適合誰看：維護 Agent SDK、迴歸評測、質量門禁和任務驗收體系的工程團隊。

試試看

為一個可判定任務寫三項 rubric，接入評分鉤子後故意製造一次遺漏，檢查證據、分項結果與失敗傳播。

注意點

釋出說明只確認鉤子存在，沒有證明評分器可靠或適合高風險決策；rubric 質量、證據可見性和偏差仍由使用者負責。

08AWS and Salesforce Agentforce美國 / 企業基礎設施2026-08-28 釋出 / 2026-08-29 觀察官方公告

Salesforce 用 SageMaker 新排程策略補齊 Agentforce 多可用區

發生了什麼：AWS 披露 Salesforce Agentforce 使用 AvailabilityZoneBalance 與 SPREAD 策略，讓模型副本按最大不平衡值分散到多可用區；擴縮容繼續維持分佈，後臺 CONSOLIDATION 會整理偏斜副本。

為什麼值得關注：共享 GPU 能降低成本，但預設放置可能把副本集中到單一區域故障域；Agent 服務的高可用必須進入排程約束。

適合誰看：在 SageMaker 上承載企業 Agent、共享 GPU 推理和多可用區 SLA 的平臺團隊。

試試看

在預生產部署四個副本跨兩區設定最大不平衡值，再模擬擴容、縮容和單區容量不足，記錄實際放置與恢復時間。

注意點

案例來自 AWS 與 Salesforce，嚴格平衡會受例項容量限制並可能只完成部分部署；策略也不替代跨區資料與依賴容災。

本期觀察：當會話、評測、快取、交易和故障域都擁有明確介面，Agent 才從一次效能力變成可治理的系統。下一步真正值得比較的，是這些控制面能否跨程序、跨區域和跨組織保持一致。
