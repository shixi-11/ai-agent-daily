01Claude Code美國 / 全球開發者2026-08-27 釋出 / 2026-08-28 觀察官方釋出

Claude Code 2.1.248 讓受限模式成為硬邊界

發生了什麼：Anthropic 為 Claude Code 2.1.248 新增 --restricted：預設移除命令、程式碼執行和 WebFetch 工具，將檔案工具限制在工作目錄，拒絕 bypassPermissions，並忽略使用者、專案和本地設定。版本還把跨會話訊息擴至 Bedrock、Vertex 與 Foundry，並修復長會話快取和憑據檔案上傳邊界。

為什麼值得關注：編碼 Agent 開始提供可直接啟用的低許可權執行面，而不是隻靠團隊手寫提示詞約束工具。

適合誰看：在企業倉庫、第三方模型閘道器或遠端會話中執行 Claude Code 的團隊。

試試看

在無敏感資料的測試倉庫對比普通模式與 --restricted，逐項記錄可見工具、可讀路徑、設定載入和跨會話訊息行為。

注意點

受限模式仍保留工作目錄內的檔案工具，也允許顯式加入 WebFetch；它縮小預設許可權，但不替代容器、網路隔離、程式碼審查與組織策略。

02CrewAI美國 / 全球開發者2026-08-27 釋出 / 2026-08-28 觀察官方釋出

CrewAI 1.15.18 把會話式 Flow 推入穩定版

發生了什麼：CrewAI 1.15.18 將 conversational flows 提升為穩定能力，讓宣告式聊天 Flow 自帶狀態結構、路由響應格式與 crew 風格模型配置。版本同時修復空最終答案時工具結果丟失、會話角色錯位、失敗任務誤記成功，以及恢復被抑制時缺少生命週期事件。

為什麼值得關注：會話不再只是訊息歷史，而開始成為帶型別狀態、路由與終態證據的可編排工作單元。

適合誰看：用 CrewAI 構建客服、運營流程、長會話工作流和可觀測 Agent 的團隊。

試試看

先做一個兩狀態的脫敏聊天 Flow，分別觸發正常結束、空答案和失敗恢復，檢查狀態形狀、角色與生命週期事件是否一致。

注意點

“穩定”是專案釋出階段宣告，不等於所有併發、儲存和外部工具組合都已生產驗證；複雜 Flow 仍需故障注入與恢復測試。

03Amazon Bedrock India印度 / 資料駐留場景2026-08-27 釋出 / 2026-08-28 觀察官方公告

Amazon Bedrock 在印度境內執行 OpenAI 模型

發生了什麼：AWS 為印度推出 OpenAI GPT-5.6 Terra 與 Luna 的地域推理配置，請求只在孟買和海得拉巴區域間排程。兩款模型支援 100 萬 token 上下文、文字與影象輸入，併相容 OpenAI Responses、Chat Completions 和 Bedrock Converse API；賬單、配額與日誌留在源區域。

為什麼值得關注：模型接入正在從“能不能呼叫”轉向“資料在哪處理、容量如何跨區排程、審計落在哪個控制面”。

適合誰看：服務印度金融、醫療、公共部門及其他資料駐留敏感場景的 Agent 團隊。

試試看

用脫敏長文件分別呼叫 in. 地域配置與 global. 配置，對比路由範圍、CloudTrail 記錄、快取命中和高峰吞吐。

注意點

印度地域配置不包含 Sol；被自動濫用檢測標記的 GPT-5.6 內容可能被離線保留。資料駐留也不自動滿足全部行業合規要求。

04Kimi Code中國 / 全球開發者2026-08-27 釋出 / 2026-08-28 觀察官方開源釋出GitHub Stars 7,118許可證 MIT

Kimi Code 0.39 開啟分叉子智慧體與 Tower 編排

發生了什麼：Moonshot AI 釋出 Kimi Code 0.39.0：子 Agent 與 swarm 可選擇攜帶呼叫方對話快照，新增實驗性 Tower 多智慧體編排和遠端控制；前臺 Bash 或子 Agent 也可在執行中轉入後臺。版本還限制遠端終端只在 loopback 繫結下可用，並修復中斷會話恢復崩潰。

為什麼值得關注：多 Agent 協作開始把上下文繼承、前後臺切換、遠端訪問與恢復放進同一個會話生命週期。

適合誰看：使用 Kimi Code、ACP、子 Agent 和移動端遠端檢視編碼任務的開發者。

試試看

在測試倉庫分別啟用 subagent_fork 與 Tower，只交付一個可撤銷任務，記錄對話繼承、後臺切換、恢復和終止後的真實狀態。

注意點

Tower、分叉與遠端控制均為實驗功能，需要顯式開關；會話快照會擴大上下文與敏感資訊傳播範圍，遠端訪問也應保持最小暴露。

05Strands Agents美國 / 全球開發者2026-08-27 釋出 / 2026-08-28 觀察官方開源釋出GitHub Stars 7,033許可證 Apache-2.0

Strands Agents 1.54 接上路由、取消與檔案記憶

發生了什麼：Strands Agents Python 1.54 與 TypeScript 1.15 同步加入可配置模型路由、Agent session_id、外部取消訊號和 FileMemoryStore；TypeScript 還新增程序內任務引擎。版本修正快取 token 計入上下文與壓縮基線，並將取消訊號繼續傳給 OpenAI 提供方。

為什麼值得關注：路由、會話身份、持久記憶與取消必須共享同一執行語義，才能避免模型切換後留下失控任務或錯誤上下文。

適合誰看：維護多模型 Agent、長任務、檔案記憶與跨語言 SDK 的平臺團隊。

試試看

建立兩模型路由和 FileMemoryStore，在工具執行中注入取消，再檢查會話 ID、快取計數、記憶落盤與提供方是否同時停止。

注意點

外部取消訊號與檔案記憶只是基礎介面，不自動提供分散式事務、加密、跨程序一致性或崩潰後的完整恢復。

06Microsoft SQuadGen中美 / 3D 研究2026-08-27 釋出 / 2026-08-28 觀察官方模型與程式碼GitHub Stars 0許可證 MIT

Microsoft 開放 SQuadGen 3D 四邊形佈局模型

發生了什麼：微軟亞洲研究院與清華團隊開放 SQuadGen 的 MIT 權重、配置和推理程式碼。系統用 Chart Distance Fields 表示 3D 表面的四邊形佈局，組合約 107M 的 Geometry-AE、115M 的 SQ-VAE 與 802M 的擴散模型，從三角網格生成可供後續建模和編輯的佈局。

為什麼值得關注：生成式 3D 正從外觀與幾何表面繼續進入拓撲佈局，為資產編輯、重建和工業建模提供新的學習型中間表示。

適合誰看：研究 3D 生成、網格重拓撲、數字內容生產和幾何 Agent 的團隊。

試試看

下載官方檢查點，用乾淨的非敏感三角網格跑一次 4096 點推理，再人工檢查拓撲、邊流、耗時和後續編輯可用性。

注意點

這是研究原型，不保證網格有效性、可製造性或 CAD 約束；官方 A100 測試中擴散生成約需 65.9 秒，複雜和域外網格可能明顯退化。

07NVIDIA Vera CPU美國 / 全球基礎設施2026-08-27 釋出 / 2026-08-28 觀察官方公告

NVIDIA Vera CPU 開始向 Agent 基礎設施交付

發生了什麼：NVIDIA 更新 Vera CPU 進展，稱這款面向 Agent 工作負載的首款自研 CPU 已開始規模交付；AWS 收到首臺 Vera CPU 伺服器與 Vera Rubin GPU，此前 Anthropic、OpenAI、SpaceXAI 和 OCI 已接收系統。Vera 配備 88 個 Olympus 核心與 1.2TB/s 記憶體頻寬。

為什麼值得關注：工具呼叫、沙箱、編排、長上下文檢索和強化學習都把壓力移到 CPU，Agent 基礎設施不再只是增加 GPU。

適合誰看：規劃 Agent 叢集、CPU-GPU 協同、雲容量和推理成本的基礎設施團隊。

試試看

先把現有 Agent 負載拆成模型計算、檢索、工具、編排與沙箱五類，測出 CPU 飽和和 GPU 空轉比例，再判斷專用 CPU 的價值。

注意點

最高 1.8 倍單核效能與 2 倍能效來自 NVIDIA 口徑，公開資料沒有給出完整同代、同功耗、同工作負載的獨立對照。

Google Earth AI 自動完成行星級預測流程

發生了什麼：Google Research 釋出實驗性的 Planetary Prediction Engine。系統從自然語言問題出發，用 LLM 編排地理資料選擇、多模態資料整理、模型訓練與評估，並以不透明控制代碼在階段間傳遞資料，避免把大型資料集塞進提示詞；內部 Feature Gate 會過濾四類目標洩漏。

為什麼值得關注：Agent 正從呼叫現成資料表，走向自動發現證據、構造資料、訓練模型並生成可核查報告的完整研究流程。

適合誰看：做地理空間、公共衛生、糧食安全、災害預測和科學 Agent 的研究團隊。

試試看

先復現一個公開小型空間迴歸任務，逐階段保留資料來源、特徵剔除、訓練配置和誤差，再和人工管線比較。

注意點

PPE 仍是實驗研究能力，結果來自 Google 自身評測；開放網路取數會引入來源質量、時間漂移和許可問題，也不能替代領域專家複核。

本期觀察：Agent 產業已經進入“系統工程”階段。許可權、取消、狀態、地域、CPU 和研究中間產物，正在共同決定模型能否真正走進生產。
