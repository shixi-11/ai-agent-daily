RISC機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它還要持續行動、扛住故障、抵禦越權，並進入真實組織協作。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體持久執行、容錯、恢復與水平擴充套件。身體站不住，一次故障就會把工作清空。
I｜智慧 / 大腦模型迴圈、記憶、工具與編排。它決定 Agent 如何思考、呼叫和完成複雜工作。
S｜安全 / 免疫能力物件、策略審批、回滾與審計。沒有免疫，恢復與連線會擴大失控半徑。
C｜連線 / 社會跨公司授權、中立基底、會話型別與生態連線。沒有社會介面，Agent 只能停在單一產品裡。

01Anthropic Claude Code美國 / 全球企業2026-08-21 釋出 / 2026-08-22 觀察官方釋出

Claude Code 把美國本地推理的 10% 溢價寫進成本面板

發生了什麼：Claude Code 2.1.239 讓 /cost、狀態列和預算上限計入美國境內推理的 1.1 倍資料駐留溢價；同版還修復 Bedrock 流經丟失 Content-Type 的代理時，每輪被非流式重跑而悄悄產生雙倍 API 呼叫的問題。

為什麼值得關注：資料駐留第一次以清晰的 10% 價格出現在開發者日常介面，合規與網路配置都開始直接進入 Agent 成本。

適合誰看：受資料駐留約束的企業開發者、FinOps、雲平臺與採購團隊。

試試看

在測試工作區比較預設與美國境內推理的 /cost，並核對 Bedrock 代理後的請求次數和賬單。

注意點

10% 僅是該產品的美國境內推理溢價，不能外推為整個行業的資料駐留成本。

02Pydantic AI全球開源 / Python2026-08-21 釋出 / 2026-08-22 觀察官方釋出

Pydantic AI 2.33 修補 Anthropic 1.0 升級造成的執行時斷裂

發生了什麼：Anthropic Python SDK 1.0 改用 httpx2 並移除舊 httpx 支援後，舊版 Pydantic AI 的寬鬆依賴可在全新安裝中解析到不相容組合並執行失敗；2.33 改為支援並要求 anthropic 1.0，舊版需暫時固定 anthropic<1。

為什麼值得關注：Agent 框架與模型 SDK 的版本邊界會在沒有程式碼改動時破壞生產環境，寬鬆依賴本身也是執行風險。

適合誰看：使用 Pydantic AI 接 Anthropic 或依賴自動升級的 Python 團隊。

試試看

在隔離環境重建 lockfile；升級到 2.33，或為舊專案臨時固定 anthropic<1，並跑一次真實呼叫。

注意點

修復聚焦 Anthropic provider 相容，不代表所有 provider 和自定義 HTTP client 都無需迴歸。

03E2B Python SDK美國 / 全球開發者2026-08-21 釋出 / 2026-08-22 觀察官方釋出

E2B 2.45.1 不再為流式檔案寫入複製一整份記憶體映象

發生了什麼：E2B Python SDK 2.45.1 將共享重試傳輸改為 UNBUFFERED，避免 streamed files.write 或 volume.write_file 在傳送時為了可重放而複製完整請求體；連線建立前仍可重試，一旦開始讀取流就不再重放。

為什麼值得關注：大檔案上傳不應讓 Agent 沙箱客戶端的峰值記憶體隨檔案大小再翻一份，重試邊界也因此更明確。

適合誰看：向 Agent 沙箱上傳大資料集、模型產物、構建目錄或卷檔案的 Python 團隊。

試試看

用同一大檔案比較升級前後的峰值記憶體，並在連線建立前後分別注入斷網觀察重試行為。

注意點

UNBUFFERED 會縮小可重放範圍；傳送開始後的失敗仍需呼叫方決定是否安全重試。

04Microsoft Agent Framework美國 / 全球開源2026-08-21 釋出 / 2026-08-22 觀察官方釋出

Microsoft Agent Framework 1.15 把恢復、審批和介面生成接成一條工作流

發生了什麼：Python 1.15 新增 A2UI 生成式介面、Cosmos 工作流檢查點型別註冊、Foundry Hosted Agents 的 steering、retry 與 recovery，並持久化審批狀態；同時保留工具訊息 ID、恢復載荷和 fan-in trace 上下文。

為什麼值得關注：Agent 生成介面之後，審批、檢查點、恢復與追蹤不能各自丟狀態；這個版本開始把它們當成同一條執行鏈。

適合誰看：構建長時工作流、企業審批、A2A 或生成式介面的 Python 團隊。

試試看

執行官方長工作流樣例，故意中斷後恢復，檢查審批值、工具訊息 ID 和 JSON resume payload 是否完整。

注意點

版本提供框架與樣例，不等於所有外部副作用都具備原子回滾或跨雲一致性。

05Moonshot AI Kimi Code中國 / 全球開源2026-08-20 釋出 / 2026-08-22 觀察官方釋出

Kimi Code 0.38 讓父 Agent 在當前回合等待後臺任務

發生了什麼：Kimi Code 0.38 新增 WaitFor，父 Agent 可在當前回合等待後臺任務完成；子 Agent 預設不能繼續生成子 Agent，編輯已有檔案前必須先讀取，磁碟內容變化時拒絕寫入，官方資料來源外掛還新增 13 個國內外資料來源。

為什麼值得關注：等待、併發層級和先讀後寫從提示習慣變成明確工具規則，能減少後臺任務失聯和覆蓋他人修改。

適合誰看：使用多 Agent 程式設計、後臺委派、Skills 或資料外掛的中國與全球開發者。

試試看

啟動一個後臺子任務並呼叫 WaitFor，再從外部修改目標檔案，確認寫入被拒絕且等待狀態可見。

注意點

WaitFor 只證明當前執行中的等待體驗，不證明程序崩潰後仍能跨節點恢復。

06OpenHands美國 / 全球開源2026-08-21 釋出 / 2026-08-22 觀察官方釋出

OpenHands 1.15 讓自動化目錄能攜帶指令碼包和版本來源

發生了什麼：OpenHands 1.15 允許從自動化目錄安裝隨條目分發的指令碼包，傳送版本化 setup 條目的模板來源，並強化 Add/Import 流程；同版修復 Agent profile 靜默降級、模型選擇漂移和事件連線掛死。

為什麼值得關注：自動化目錄開始像可安裝的 Skill 供應鏈：不僅分發說明，還分發指令碼，並需要知道模板來自哪裡、用了哪個版本。

適合誰看：維護 OpenHands 自動化、企業模板目錄、Skills 市場或內部開發平臺的團隊。

試試看

安裝一個帶指令碼包的目錄條目，檢查模板來源、版本、實際指令碼清單和升級後的差異。

注意點

來源證明了分發與 provenance 欄位，不代表目錄中的每個指令碼都已透過安全審計。

07Ollama全球開源 / Apple Silicon2026-08-21 釋出 / 2026-08-22 觀察官方預釋出

Ollama 0.33 RC 讓 MLX 字首快取跨取消與恢復繼續有效

發生了什麼：Ollama 0.33.0 RC 更新 MLX runner，讓字首快取恢復點在 prefill 被取消後仍可用於恢復；同版新增 Claude 桌面應用入口、連線應用體驗和 Claude 模型管理，併為 DeepSeek Harness 增加 npx 回退。

為什麼值得關注：長上下文預填充被取消不必從零開始，本地推理的恢復體驗開始進入快取架構，而不只是介面層重試。

適合誰看：在 Apple Silicon 上執行本地模型、長上下文助手或桌面 Agent 的使用者。

試試看

用長字首觸發 prefill，中途取消後恢復，記錄恢復時間、快取命中和記憶體佔用。

注意點

這是候選版本；快取恢復點不等於完整對話狀態或外部工具動作可恢復。

全球技術與市場觀察

08ComponentBench Research全球研究2026-08-21 釋出 / 2026-08-22 觀察一手研究

ComponentBench 顯示同一模型只因操作介面不同就相差 30 個百分點

發生了什麼：ComponentBench 用 97 類網頁元件構造 2910 個可程式驗證任務，並在統一 harness 中評測七個模型。僅改變觀察與動作空間，同一 GPT-5 mini 的成功率就從 accessibility tree 的 83.1% 降到純座標控制的 48.9%。

為什麼值得關注：電腦 Agent 的成績不只由模型決定，DOM、無障礙樹、座標和動作介面本身就能製造超過 30 個百分點的差距。

適合誰看：評測或採購電腦 Agent、瀏覽器自動化、GUI harness 與模型路由的團隊。

試試看

用團隊常見的開關、選單和拖拽任務，分別跑 accessibility tree 與座標模式並記錄成功率和耗時。

注意點

論文中的 2910 項元件任務診斷中層互動，不能替代真實業務的長流程驗收；最快配置仍比人類慢 3.7 倍。

市場觀察：資料駐留溢價、依賴斷裂、Skill來源、快取恢復和操作介面看似分散，卻共同說明一件事：Agent產品的可靠性正由模型之外的工程合同決定。
