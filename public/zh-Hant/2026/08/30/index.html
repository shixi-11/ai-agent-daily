RISC機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它還要持續行動、扛住故障、抵禦越權，並進入真實組織協作。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體持久執行、容錯、恢復與水平擴充套件。身體站不住，一次故障就會把工作清空。
I｜智慧 / 大腦模型迴圈、記憶、工具與編排。它決定 Agent 如何思考、呼叫和完成複雜工作。
S｜安全 / 免疫能力物件、策略審批、回滾與審計。沒有免疫，恢復與連線會擴大失控半徑。
C｜連線 / 社會跨公司授權、中立基底、會話型別與生態連線。沒有社會介面，Agent 只能停在單一產品裡。

01Stable Audio 3 Optimized英國 / 全球音訊開發者2026-05-18 釋出 / 2026-08-30 觀察官方模型更新

Stable Audio 3 撤下校準錯誤的 FP8 引擎

發生了什麼：Stability AI 在最佳化權重頁撤下校準錯誤的 SM120 FP8 編碼器與已過時的 SM90 引擎，把舊 ONNX 移入 legacy，併發布帶限幅器、固定輸出上限和重新校準啟用尺度的可構建 ONNX。模型本體並非今日首發，變化發生在 8 月 27—28 日的部署製品層。

為什麼值得關注：本地生成模型的風險不只來自權重；錯誤量化尺度和過時引擎會把音質、削波與復現偏差帶進整條生產鏈。

適合誰看：部署 Stable Audio 3、ONNX、TensorRT 或 FP8 音訊生成的團隊。

試試看

先鎖定檔案雜湊，再用同一批提示比較新版與 legacy 引擎的峰值、削波、響度和生成耗時，確認回退路徑可用。

注意點

最佳化倉庫明確標為實驗製品，使用 Stability AI Community License；硬體特定加速結果不能直接外推到所有裝置或商業場景。

MiniMax CLI 1.0.21 給 H3 Skill 加上超時邊界

發生了什麼：MiniMax CLI 1.0.21 為 H3 影片生成補上獨立 Agent Skill，並加固影片 SDK、停滯流超時與資源下載上限；語音合成增加情緒、文字規範化和 LaTeX 朗讀引數，同時下線已經不再符合當前 API 的 Music CLI 與 SDK。

注意點

Pydantic AI 2.36 開放持久操作後端介面

發生了什麼：Pydantic AI 2.36 新增 `@durable_operation`，要求每個持久操作顯式命名，並開放第三方持久執行引擎可實現的公共後端 API；同時給 instruction part 增加穩定 ID，為 clai 補上 MCP 配置與工具呼叫流式輸出。

為什麼值得關注：長流程開始把“哪一步可恢復、由誰接管、怎樣避免重複執行”寫進框架介面，而不是留給業務層臨時拼接。

適合誰看：使用 Temporal、Prefect 或自研引擎承載長時 Agent 工作流的團隊。

試試看

把一個可撤銷外部呼叫標成持久操作，模擬程序中斷與重複投遞，檢查操作名、快取鍵、恢復位置和副作用是否一致。

注意點

公共後端 API 只提供接點，不自動保證外部服務冪等、補償事務或跨引擎語義一致；接入前仍需故障測試。

04OpenAI Codex美國 / 全球開發者2026-08-29 釋出 / 2026-08-30 觀察官方開源釋出GitHub Stars 119,808許可證 Apache-2.0

Codex 0.151 允許擴充套件改寫 MCP 工具結果

發生了什麼：Codex 0.151 讓擴充套件在 MCP 工具結果進入模型前檢查或替換內容，併為可選 MCP 服務增加可配置發現寬限期。版本還保留恢復後的許可權配置，阻止 `/cd` 弱化沙箱，按真實執行器系統與路徑強制遠端隔離，並把子 Agent token 計入根目標預算。

為什麼值得關注：工具結果第一次進入可程式設計檢查點，但這也把新的信任邊界放到擴充套件層；預算、許可權和結果變換必須一起審計。

適合誰看：維護 Codex、MCP 擴充套件、遠端沙箱和多 Agent 預算控制的團隊。

試試看

寫一個只脫敏測試欄位的結果處理擴充套件，再恢復舊會話並切換目錄，檢查輸出、許可權配置、沙箱範圍與根預算。

注意點

擴充套件可替換工具結果，意味著擴充套件本身也能改變模型證據；應限定來源、版本與許可權，並保留原始結果供審計。

Microsoft 把音訊描述重寫成人工可編輯流水線

發生了什麼：Microsoft 在 8 月 29 日重寫 AI Audio Descriptions：系統分析 MP4、找出對白間隙並生成 WebVTT 草稿，由編輯者修改後再用語音合成、壓低原聲並混成新影片。新架構以 Python 引擎統一 Studio 與 CLI，原生 FFmpeg 渲染移到服務端。

注意點

當前版本是單機本地檔案方案，沒有認證、多機協調或共享雲端儲存；README 明確要求未補安全控制前只繫結本機迴環地址。

注意點

官方稱大規模 GLM-5.3 負載已驗證，但沒有公開完整硬體、規模和復現實驗；其他模型仍需自行建立對齊基線。

timm 1.0.29 加入 LowFormer 與 Agent 發現的修復

注意點

釋出說明沒有逐項標明哪些缺陷由哪類 Agent 發現，也不證明自動發現結果天然正確；仍應檢視對應 PR 與測試。
