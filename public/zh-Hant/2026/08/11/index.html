05E2B Python SDK全球/開源2026-08-10 釋出 / 2026-08-11 觀察官方釋出

E2B Python SDK 2.38 把沙箱流量收進統一傳輸與整次呼叫截止時間

發生了什麼：E2B Python SDK 2.38 將 envd HTTP 與 REST API 客戶端遷移到共享的 pyqwest 傳輸；非流式讀取和緩衝上傳的 request_timeout 變成整次呼叫截止時間，連線失敗預設重試 3 次，程序內執行緒/事件迴圈共享連線池。

對 ALUX 的關係：生產機體需要可解釋的時間預算，而不是每個 socket 階段各自計時後讓總時長失控。統一傳輸也讓錯誤、重試和連線身份更容易進入同一執行收據。

可行動建議與產出物：可沉澱一份 Sandbox I/O Budget Schema，區分總截止、空閒截止、連線重試與可取消性。 可沉澱為：Sandbox I/O Budget Schema v0。

RISC：R 主 · 強韌 / 機體

這條訊息主要動到機器人的強韌/機體：統一傳輸、整次呼叫截止與連線重試決定沙箱 I/O 在真實負載下能否收斂。

容錯能力是連線建立失敗預設重試 3 次，並保持穩定的 httpx 錯誤型別。
持久執行部分整次呼叫截止和流式 idle timeout 可約束掛起，但流式總時長仍可預設無界。
合作 / 學習視窗

若接入 E2B，可直接把其明確的 httpx 相容錯誤型別對映為 ALUX 故障分類。 採用 whole-call deadline、idle timeout、connect-only retry 的分層時間語義。

風險邊界

流式下載預設總時長仍可無界；同步客戶端不能中斷阻塞讀取，只依賴傳輸 idle bound。

今天的新變化

2.38.0 將此前分散於執行緒/事件迴圈的客戶端收斂為共享傳輸，並收緊 timeout 的總時長含義。

策略審批部分OAuth 提供授權邊界，釋出未描述重新整理時的策略複核或人工審批。

技術 / 產品啟發

優先產品：Runtime Resume & Effect Receipt v0。恢復收據不只儲存 checkpoint，還要儲存新增輸入順序、審批物件、憑據 epoch、已發生效果與補償能力。
優先 Demo：讓 OpenAI Agents SDK 在暫停後加入一條 pending input，經 ALUX 校驗舊審批是否仍對同一 invocation 有效；工具執行在 E2B 沙箱，Phoenix 接收 trace。若外部 mutation 不具備物件 capability 或 compensation_ref，執行時阻止提交併留下可重放裁決。

風險邊界

ALUX 仍不能被描述為已經完整交付的智慧體平臺。底層 TVM 已具備原生併發、持久執行、能力安全、執行記錄與逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤和評估工具仍待構建與融資。TVM 不會讓 LLM 本身確定性；它記錄模型輸出與環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。RunState、沙箱清理、OTel span、OAuth 重新整理和 API Key 控制面都不能單獨證明跨步驟原子回滾、不可偽造能力或中立跨公司協作；TechCrunch 案例也不能推導所有 本地 Agent 或 Claude 執行都會越權。
