RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

容錯能力是官方釋出在 v6/v7 之間歸一化工具結果、流介面與檔案輸出，並分別執行測試。
故障恢復部分事件形態跨版本穩定，但釋出沒有 checkpoint、resume 或補償能力。
合作/學習視窗

可設計 Event Normalization Receipt，作為 Cloudflare Agents 與 ALUX 觀測介面。 學習跨大版本事件歸一化、相容測試和已知資訊損失披露。

風險邊界

雙版本支援主要是相容工程，不證明工具效果可回滾、會話可持久或跨公司中立協作。

今天的新變化

0.19 首次公開描述 AI SDK v6/v7 的跨版本歸一化邊界，並明確 stepNumber 等無法保留的欄位。

融資 / 合作視窗

最直接視窗：E2B 與 Strands 提供效果安全和並行恢復樣本；Microsoft 與 Cloudflare 提供跨模型、跨版本重放樣本；Langfuse 與 Deep Agents 提供審計最小披露和能力快照入口；Qwen、Pydantic AI 提供目標與工具編排介面。
融資敘事視窗：今天沒有新的可靠融資金額進入正文。更有力的資本訊號是：主流框架已開始為“恢復後是否重複副作用、配錯狀態或洩露證據”逐項補丁；ALUX 可以把這些分散責任收進同一個生產級執行時契約。

技術 / 產品啟發

優先產品：Effect-Safe Recovery Contract v0。欄位建議包括 attempt_id、delivery_state、effect_cursor、parallel_branch_set、shared_context_digest、capability_snapshot、model_schema_version、retry_class、compensation_verdict 與 evidence_refs。
優先 Demo：讓 Qwen Goal v3 透過 Pydantic AI 呼叫 E2B 工具，並以 Strands 並行分支匯合；在 RPC 交付未知時升級 Cloudflare 事件 schema、輪換 Langfuse secret，再由 Microsoft replay 恢復，展示 ALUX 如何拒絕重複副作用並保留最小披露證據。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。連線重試、訊息 replay、能力快照、trace、事件歸一化和目標驗收都不能自動證明外部副作用已去重、物件能力不可偽造、跨步驟原子回滾或中立跨公司協作。
