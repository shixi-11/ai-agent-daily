RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

發生了什麼：2.1.218 將 /code-review 改為後臺子 Agent，避免審查佔滿主會話，並修復執行器 teardown 競態、工具中止後 transcript 留下不配對 tool_use、錯誤靜默丟失及 MCP 連線錯誤可見性。

對 ALUX 的關係：後臺子 Agent 讓並行工作更順滑，也暴露主會話、後臺會話和工具狀態之間的生命週期責任。ALUX 可把子 Agent 執行、取消、轉錄完整性與主任務提交繫結到同一可重放狀態機。

可行動建議與產出物：建議形成 Background Subagent Lifecycle Contract，定義 parent、child、cancel、tool state、transcript commit 和 final handoff。 可沉澱為：Background Subagent Lifecycle Contract v0。

RISC：I 主 · 智慧 / 大腦R 輔 · 強韌 / 機體

這條訊息主要動到機器人的智慧 / 大腦：程式碼審查被拆到後臺子 Agent，改變任務編排；強韌 / 機體為次維度，因為 teardown 競態與 transcript 裂縫直接影響執行完整性。

工具編排是程式碼審查明確改由後臺子 Agent 執行，主會話可繼續工作。
模型迴圈部分後臺審查形成獨立模型工作迴路，但公開說明沒有完整計劃與反思協議。
合作/學習視窗

可把 Claude Code 作為 Background Subagent Lifecycle Test，驗證取消、中止、主會話恢復與 transcript 完整性。 學習後臺審查、會話切換和 MCP 故障反饋的使用者體驗。

風險邊界

後臺化不等於持久執行；修復競態與不配對 transcript 說明此前存在狀態裂縫，釋出說明也沒有證明外部效果去重、回滾或跨公司協作。

今天的新變化

2.1.218 將程式碼審查遷入後臺子 Agent，並集中修復執行器競態、工具中止和轉錄完整性問題。

融資 / 合作視窗

最直接視窗：Temporal 與 Pydantic AI 提供耐久執行和恢復語義；AgentScope、Microsoft Agent Framework 與 Agno 提供組織連線和 A2A/Slack 會話樣本；Deep Agents、Langfuse 與 Claude Code 提供工具邊界、證據等級和子 Agent 生命週期樣本。
融資敘事視窗：今天沒有新的可靠融資金額進入正文。更強的資本敘事是：框架公司正在分別為載荷外接、組織共享、型別化互操作、執行身份、預設拒絕和觀測完整性投入工程成本；ALUX 的機會是把這些碎片收進統一生產執行時。

技術 / 產品啟發

優先產品：Durable Agent State Envelope v0。欄位建議包括 state_ref、content_hash、owner、capability_scope、session_type、runtime_backend、heartbeat_cursor、recovery_verdict、effect_commit 與 evidence_class。
優先 Demo：讓 Microsoft A2A 任務進入 AgentScope 隔離工作區，經 Pydantic AI run_id 驅動 Temporal workflow；中途外接大載荷、撤銷組織憑據並終止後臺子 Agent，展示 ALUX 如何恢復、衰減能力並證明最終效果。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。外部載荷、run_id、sandbox、組織共享、型別化 A2A、工具白名單、MCP 反饋和後臺子 Agent 都不能自動證明物件能力、跨步驟原子回滾、端到端證據完整性或中立跨公司協作。
