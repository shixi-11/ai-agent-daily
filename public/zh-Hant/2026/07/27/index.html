RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

可行動建議與產出物：建議形成 Trace Context Projection v0，繫結 workflow_run、trace_context、runtime_event_ref、process_boundary、redaction_policy 與 replay_proof_ref。 可沉澱為：Trace Context Projection v0。

今天的新變化

1.21.1 首次明確由 Temporal SDK 自身的非同步上下文承載 LangSmith tracing，追蹤責任從應用膠水下沉到執行時適配層。

融資 / 合作視窗

最直接視窗：CrewAI 與 Agno 提供技能、記憶和路由入口；Gemini CLI 與 Deep Agents 提供輸入信任和審批旁路樣本；E2B 提供製品供應鏈樣本；Strands、Pydantic AI 與 Temporal 提供狀態、證據和觀測成本介面。
融資敘事視窗：今天沒有新的可靠融資金額進入正文。更有力的資本證據是：主流 Agent 框架正在分別修補技能來源、會話串線、審批旁路、依賴漏洞和追蹤連續性；ALUX 可以把這些分散責任統一為協議級能力與可重放狀態。

技術 / 產品啟發

優先產品：Runtime Capability Provenance Receipt v0。欄位建議包括 skill_source、artifact_digest、model_route、authority_epoch、session_epoch、dependency_epoch、trace_context、effect_digest、revocation_status 與 replay_ref。
優先 Demo：讓 Agno 的實體記憶透過 CrewAI 技能呼叫 E2B 沙箱，在 Strands 中切換模型；中途觸發 Gemini fallback 與 Deep Agents 審批模式變化，再將 Pydantic AI、Temporal 的觀測投影接入，展示 ALUX 如何判斷能力來源、許可權狀態與恢復後的外部效果是否仍然一致。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。技能事件、會話輪換、審批旁路、製品升級、OTel trace 與 wire cassette 都不能自動證明物件能力不可偽造、跨步驟原子回滾、外部效果已去重或中立跨公司協作。
