這條訊息主要動到機器人的強韌 / 機體：長時間作業終於有顯式暫停入口；安全 / 免疫為次維度，因為暫停期間仍需約束能力和外部效果。

持久執行部分WaitTool 允許 Agent 在長時間作業上顯式暫停，但釋出沒有說明狀態已持久化到程序之外。

風險邊界

官方釋出只證明可以暫停等待，沒有證明程序崩潰後恢復、外部效果去重、能力在暫停期間自動衰減或跨步驟原子回滾。

今天的新變化

今天的新變化是 CrewAI 首次把長時間作業的顯式等待作為正式工具釋出，而不是讓 Agent 用輪詢或普通函式呼叫自行維持。

可用 Inspector v2 構建 MCP Session Surface Conformance Pack，測試 ALUX 介面卡在三種客戶端中的一致性。 學習共享核心如何減少多客戶端語義漂移，並用引數語義區分只讀會話和可寫伺服器目錄。

風險邊界

三客戶端一致不等於服務端可信、能力不可偽造或跨公司中立；v1 只收安全修復也會形成遷移視窗風險。

今天的新變化

今天的新變化是 v2 從候選版轉為預設正式版，並用一個共享核心統一三種客戶端和新的會話 / 目錄語義。

Strands Agents 1.50.2 增加逐呼叫 MCP 取消與 Agent-as-Tool 委派

發生了什麼：Python 1.50.2 增加逐呼叫 MCP 工具取消，TypeScript 同步加入 agent-as-tool 委派；版本還修復 MCP 倒排索引去重、流式 reasoning signature 消費和雙向 Gemini Live API 適配。

對 ALUX 的關係：當一個 Agent 作為另一個 Agent 的工具時，取消必須沿委派鏈精確落到某次呼叫，而不是關閉整條會話。ALUX 可把委派能力、呼叫身份和取消 epoch 做成協議物件。

可行動建議與產出物：建議形成 Delegated Tool Cancellation Envelope v0，繫結 delegator、delegatee、tool_call_id、capability_scope、cancellation_epoch、effect_cursor 與 terminal_ack。 可沉澱為：Delegated Tool Cancellation Envelope v0。

今天的新變化

今天的新變化是 MCP 取消從會話級泛化為逐呼叫控制，並與 Agent-as-Tool 委派在同一 Harness SDK 版本線出現。

融資 / 合作視窗

最直接合作面：CrewAI、Pydantic AI、Kimi Code 與 Dify 提供暫停、取消、作用域狀態和協作恢復入口；Gemini CLI、Cloudflare Agents、MCP Inspector 與 Strands 可作為隔離、證據、連線和委派樣本。
資本敘事：今天沒有可驗證的新融資金額值得進入正文。更強的結構訊號是，主流框架正分別為等待、取消、重連、隔離、呼叫譜系和逐呼叫委派補丁；ALUX 的機會是把這些責任收斂成執行時協議。

技術 / 產品啟發

風險邊界

ALUX 仍不能被描述為已經完整交付的智慧體平臺。底層 TVM 已具備原生併發、持久執行、能力安全、執行記錄與逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤和評估工具仍待構建與融資。TVM 也不會讓 LLM 本身確定性；它記錄模型輸出與環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。WaitTool、取消重施、協作重連、作用域快照、遙測 span、MCP 2.0 或逐呼叫取消，都不能單獨證明跨程序恢復、不可偽造能力、外部效果去重、跨步驟原子回滾或中立跨公司協作。
