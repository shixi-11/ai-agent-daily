RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

對 ALUX 的關係：瀏覽 Agent 的風險集中在可訪問域名、無意載入的秘密和評估環境漂移。ALUX 可把域名策略、環境變數來源、瀏覽會話和基準版本統一進執行前能力合同。

可行動建議與產出物：可沉澱 Browser Session Capability Receipt，覆蓋 allowed_domains、credential_sources、env_autoload、navigation_effects、download_hash、benchmark_version 與 policy_verdict。 可沉澱為：Browser Session Capability Receipt v0。

RISC：S 主 · 安全 / 免疫I 輔 · 智慧 / 大腦

這條訊息主要動到機器人的安全 / 免疫：域名策略和 .env 自動載入決定瀏覽 Agent 能接觸哪些站點與秘密；智慧 / 大腦為次維度，因為 OdysseysBench 用於測量瀏覽規劃與執行能力。

策略審批部分setDomainPolicy 已有正式文件，但公開說明未證明所有導航路徑均被強制裁決。
隔離邊界部分CLI 對 .env 自動載入發出警告並允許退出，但秘密仍可能因預設行為進入會話。
合作/學習視窗

可為 Stagehand 建立 ALUX Browser Capability Adapter，用能力物件限定域名、憑據、下載、上傳和頁面副作用。 學習 Stagehand 如何把瀏覽域策略、CLI 秘密載入提醒和 Agent benchmark 放到同一版本。

風險邊界

文件化域名策略不證明策略不可繞過；.env 警告依賴操作者選擇，benchmark 也不代表真實生產站點的安全性和恢復能力。

3.7.3 把域名策略、.env 自動載入警告和 OdysseysBench 同時納入瀏覽 Agent 釋出面。

融資 / 合作視窗

技術 / 產品啟發

優先產品：Agent Continuity & Authority Envelope v0。欄位建議包括 session_id、agent_profile、tool_restrictions、workspace_root、inflight_turn、delegation_state、effect_receipt、skill_digest、capability_veto、retention_policy 與 recovery_verdict。
優先 Demo：讓 Qwen Code 接管一個長期 PR，透過 CrewAI Skill 與 Stagehand 瀏覽能力完成任務；中途重啟容器並觸發 Deep Agents 審批。最終展示 ALUX 如何恢復原 Agent 身份、證明實際工具效果、保留全域性水印並在釋放後撤銷未來能力。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。長會話修復、隔離 rollout、倉庫內接管、技能下載認證、審批資格、保留期清理和域名策略，都不能自動證明跨步驟原子回滾、物件能力或中立跨公司協作。
