RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

發生了什麼：Anthropic 同一版本修復目錄通配規則越界、PowerShell 許可權檢查繞過、Bash 檔案描述符重定向解析差異、超長命令誤判及遠端確認競態；同時補充工具來源與訊息級關聯遙測。

對 ALUX 的關係：這不是普通補丁清單，而是證明許可權分析器必須 fail closed、遠端確認必須先於執行、工具來源必須可追責。ALUX 的能力物件與逐操作策略應把這些條件固化在執行時，而不是交給前端提示框。

RISC：S 主 · 安全 / 免疫R 輔 · 強韌 / 機體

這條訊息主要動到機器人的安全/免疫：多類解析差異都可能讓危險動作越過授權；強韌/機體為次維度，因為遠端會話和長工具呼叫需要可靠心跳與確認時序。

策略審批是遠端會話必須等待本地確認，超長或分析器不確定的命令改為強制提示。

風險邊界

釋出說明證明修復存在，不等於 Claude Code 已獲得不可繞過的物件能力模型或完整回滾能力。

今天的新變化

相較 7 月 16 日對 Claude Code 的隔離與審批觀察，2.1.214 新增多 shell 許可權解析修復、遠端確認競態修復和工具來源遙測。

發生了什麼：AgentScope 新增 K8sWorkspace，覆蓋 Pod/PVC 生命週期、tar-stream 後端和 MCP Gateway；同時增加 OpenSandbox backend，讓同一框架可把 Agent 工作區落到不同執行基礎設施。

對 ALUX 的關係：執行域抽象與 ALUX 的 GLVM 方向相鄰：框架需要把工作放到合適環境，但當前仍缺少跨域能力一致性、狀態轉移收斂和中立驗證。ALUX 可提供統一能力與可重放執行契約。

可行動建議與產出物：建議形成 Execution Domain Descriptor v0，統一位置、信任級別、能力、狀態儲存、恢復和證明要求。 可沉澱為：Execution Domain Descriptor v0。

RISC：R 主 · 強韌 / 機體S 輔 · 安全 / 免疫

這條訊息主要動到機器人的強韌/機體：框架可在 Kubernetes 與獨立沙箱間選擇執行域；安全/免疫為次維度，因為每個域的許可權、租戶和資料邊界不同。

水平擴充套件是K8sWorkspace 明確管理 Pod/PVC 生命週期，適合多工作區擴充套件。
持久執行部分PVC 提供持久儲存基礎，但版本說明未證明工作流恢復語義。
合作/學習視窗

可研究 AgentScope Workspace → ALUX Execution Domain Adapter。 學習 Pod/PVC 生命週期與框架層 sandbox backend 抽象。

風險邊界

Kubernetes 與 OpenSandbox 只證明部署選擇，不證明狀態一致、能力安全或跨公司中立。

今天的新變化

7 月 16 日版本首次同時交付 Kubernetes 工作區生命週期和 OpenSandbox 後端，區別於前日 AgentID 聯邦身份訊號。

09LangChain Deep Agents Code美國/全球開源2026-07-17 / 2026-07-18 觀察官方 GitHub

Deep Agents Code 0.1.43 試驗分類器自動審批，便利性開始直接碰撞許可權責任

發生了什麼：Deep Agents Code 在實驗開關後加入 classifier-backed Auto approval mode，並補充延遲退出提示和技能名稱衝突除錯。

對 ALUX 的關係：自動審批把分類模型從建議層推到授權路徑。一旦誤判，工具呼叫會從便利功能變成責任事故。ALUX 應要求高風險能力仍受不可繞過策略、審批級別和可追責證據約束。

可行動建議與產出物：適合形成 Auto-Approval Risk Matrix，按能力危險級別定義模型可決、必須人工和禁止自動三檔。 可沉澱為：Auto-Approval Risk Matrix。

RISC：S 主 · 安全 / 免疫I 輔 · 智慧 / 大腦

這條訊息主要動到機器人的安全/免疫：分類器正在決定動作能否自動獲批；智慧/大腦為次維度，因為判斷質量依賴分類模型。

策略審批部分存在分類器自動審批，但無公開風險閾值與高危能力排除規則。
回滾審計否釋出說明未展示審批理由收據、回滾或可重放證據。
合作/學習視窗

可提供執行時策略適配與高風險能力強制人工確認。 觀察分類器審批的風險分層、誤報漏報和人機體驗。

風險邊界

功能預設隱藏在實驗開關後，公開說明沒有閾值、訓練集、誤判率或高風險動作排除表。

今天的新變化

相較 0.1.42 的外掛 GA 與 marketplace 狀態，0.1.43 首次把分類器自動審批放入實驗路徑。

融資 / 合作視窗

最直接視窗：Smartsheet 與 AWS 已把遠端 MCP 做成連線內外部 Agent 的企業入口；E2B、Agno、AgentScope 則提供不同雲執行域。ALUX 可用能力介面卡與長交易合同切入，不必爭奪上層介面。
融資敘事視窗：今天沒有值得放大的新融資數字，但產品證據更紮實：企業正在為恢復、隔離、實時授權和工具治理付費。ALUX 應把“完整機器”落實為可驗收的執行時合同與 Demo。

技術 / 產品啟發

優先產品：Agent Execution Contract v0。欄位建議包括 session_owner、checkpoint_id、capability_grant、approval_state、execution_domain、effect_receipt、retry_identity、replay_proof。
優先 Demo：讓一個企業 Agent 透過 Smartsheet MCP 領取任務，在 E2B 分叉沙箱內試跑，再由 Qwen 或 Claude Code 發起受審批工具呼叫；中途模擬故障，展示 ALUX 如何恢復同一長交易、限制能力並重放責任鏈。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。檢查點分叉、Firecracker、Kubernetes 工作區、OpenTelemetry、實時 ACL 與執行賬本，都不能自動證明跨系統原子回滾、物件能力或中立跨公司協作。
