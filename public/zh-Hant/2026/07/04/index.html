RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

01Microsoft Agent Framework美國/開源2026-06-30 / 2026-07-04官方 GitHub

Microsoft Agent Framework 1.10.0 釋出，把 Durable Task worker、工具審批、遙測和 Harness loop 推進到框架核心

發生了什麼：MAF 1.10.0 增加 standalone Durable Task worker、Foundry session helper、工具審批預設化、AgentLoop/HarnessAgent 整合、OTel tool format 與多處 checkpoint / telemetry 修復。

對 ALUX 的關係：Microsoft 正把 agent framework 從編排工具推到可託管、可恢復、可觀測的執行時。ALUX 應把它視為最接近“聯邦化 LangChain”之前半段的對照物：上層 authoring 會越來越成熟，但跨系統長交易、能力物件和可重放審計仍是空位。

可行動建議與產出物：建議形成一頁 MAF 1.10.0 vs ALUX 長交易執行時對照：Durable Task worker 對應可恢復執行，tool approval 對應能力授予，telemetry 對應可重放證據。 MAF 對比頁 + Agent trace 欄位對映草案。

RISC: R 主 · 強韌/機體次維度 S
持久執行是release 明確加入 standalone Durable Task worker 與 HarnessAgent loop。
故障恢復部分release 包含 fan-in checkpoint、workflow bugfix 與 streaming parent context 修復，但未證明跨組織恢復。
合作/學習視窗

適合面向 Microsoft/Foudry 生態做“MAF 負責 agent authoring，ALUX 負責跨組織長交易證據層”的互補敘事。

風險邊界

風險是 Microsoft 會把 durable、approval、telemetry 都向 Azure/Foundry 閉環推進，壓縮獨立執行時的話語空間。

今天的新變化

今天觀察到 1.10.0 的 durable worker、審批預設化和遙測修復，較前日 1.9.0 更接近生產執行時。

02Anthropic Claude Tag美國/全球2026-06-23 / 2026-07-04官方釋出

Anthropic Claude Tag 在 Slack 中讓團隊共享一個可記憶、可授權、可非同步工作的 Claude

發生了什麼：Claude Tag 進入 Slack，企業/團隊使用者可在頻道里 @Claude，授予特定工具和資料訪問；它能記憶頻道上下文、主動跟進，並以 scoped identity 區分渠道和用途。

對 ALUX 的關係：Claude Tag 把單人對話變成組織裡的“共同工作體”。這會讓會話邊界、記憶歸屬、工具授權和跨團隊交接變成產品問題，正好貼合 ALUX 未來跨公司協作和會話型別敘事。

可行動建議與產出物：建議整理“Channel Agent Session Type”說明頁，用 Claude Tag 做反例：廠商內共享很強，但跨公司授權和可重放審計仍未被證明。 Channel Agent Session Type 草案。

RISC: C 主 · 連線/社會次維度 S
會話型別是Claude Tag 明確是 Slack 頻道里的多人共享 Claude，任何人可接續上下文。
生態連線是來源說明可接入被授權的 tools、data、codebases。
合作/學習視窗

可面向 Slack/Teams/飛書生態夥伴討論中立 agent session runtime，而不是讓每個模型廠商獨佔團隊上下文。

風險邊界

Anthropic 先佔住“團隊裡的 Claude”入口，ALUX 不能與它搶聊天介面，應講跨廠商、跨公司、可審計的會話基底。

今天的新變化

與 Workspace Agents 同線，但 Claude Tag 把共享會話和頻道級許可權講得更清楚。

03OpenAI Codex美國/全球2026-06-25 / 2026-07-04官方研究

OpenAI 釋出 Codex 經濟研究：Agent 工作單位從一次回覆轉向分鐘到小時級委派任務

發生了什麼：OpenAI 報告顯示 Codex 使用者正在把更長、更復雜、跨職能的任務交給 agent；到 2026 年 5 月，80.6% 抽樣個人使用者至少提交過一次估計超過 30 分鐘人類工作的請求。

對 ALUX 的關係：這是今天最高價值訊號：當 Codex 執行時間被經濟研究量化，ALUX 的“長交易”不再是技術想象，而是企業已經在消耗的 agentic labor。融資敘事可從“更聰明模型”轉向“誰為長程 agent 勞動提供執行時責任鏈”。

可行動建議與產出物：建議把今日主敘事定為“Agentic labor needs runtime accountability”，並形成一頁長交易工時證據圖。 長交易工時證據圖 + investor why-now 頁。

RISC: R 主 · 強韌/機體次維度 C
持久執行部分來源證明使用者把分鐘到小時級任務交給 Codex，但未說明底層恢復機制。
水平擴充套件是報告覆蓋 individual、organizational 與 OpenAI 內部跨部門使用，並提到多 agent 並行。
合作/學習視窗

可與 eval、observability、企業流程諮詢方合作，把 agent 工時轉化為 trace、成本、風險和恢復指標。

風險邊界

報告資料來自 OpenAI 自身與 Codex 樣本，不能直接外推到所有行業；對外使用需標明方向性。

今天的新變化

此前已觀察 OpenAI agents work 趨勢；今天選入是為了支撐“長程工作負載”已成經濟研究物件。

04Anthropic Claude Sonnet 5美國/全球2026-06-30 / 2026-07-04官方釋出

Anthropic Claude Sonnet 5 下放 agentic 執行能力，成本層開始承接瀏覽、終端和持續編碼

發生了什麼：Sonnet 5 被定位為最 agentic 的 Sonnet 模型，可規劃、使用瀏覽器和終端，並在 Claude Code 與平臺 API 中提供更低成本的持續執行能力。

對 ALUX 的關係：Sonnet 5 說明強大腦會繼續降價並下放到更廣可用層。ALUX 不應去比模型能力，而要利用這個趨勢證明：當大腦更便宜、更普及，企業更缺機體、免疫和社會。

可行動建議與產出物：建議在 deck 中加入“大腦快速商品化，執行時責任稀缺化”頁，Sonnet 5 作為證據之一。 大腦商品化 vs 執行時稀缺化敘事頁。

RISC: I 主 · 智慧/大腦次維度 R
模型迴圈是來源稱 Sonnet 5 可 make plans、use browsers and terminals、run autonomously。
工具編排是瀏覽器和終端工具使用是釋出核心。
合作/學習視窗

可把 ALUX 定位成 Claude/OpenAI/Qwen 等多模型的中立執行時，不依賴某一個大腦。

風險邊界

不能把 Sonnet 5 的安全評估等同於企業級許可權安全；模型更安全不代表工具呼叫邊界自動安全。

今天的新變化

7 月初的關鍵變化是 Sonnet 級成本層接近 Opus 4.8 的部分 agent 能力，讓“大腦商品化”更快。

05Amazon Bedrock AgentCore美國/全球雲平臺2026-06 / 2026-07-04官方文件

AWS Bedrock AgentCore June notes：Identity 引用既有 Secrets、Runtime 持久終端、Step Functions 嵌入 Harness

發生了什麼：AgentCore 允許 Identity 引用既有 Secrets Manager ARN；Runtime 支援持久互動式 shell；Step Functions 可原生呼叫 AgentCore harness 幷包裹人工審批、錯誤處理和條件路由。

對 ALUX 的關係：AWS 正把 agent 納入既有云身份、Secrets、Step Functions 和 sandbox 體系，驗證企業會先從治理與工作流接入購買 agent runtime。ALUX 的差異要放在跨雲、跨公司、可重放證據。

可行動建議與產出物：建議補一張“Cloud AgentCore vs Neutral Agent Runtime”表格，突出雲內治理與中立長交易的邊界。 Cloud AgentCore vs Neutral Agent Runtime 表格。

RISC: S 主 · 安全/免疫次維度 R
能力物件部分AgentCore Identity 可引用 Secrets ARN 並用客戶治理策略管理，但不是物件能力模型。
策略審批是Step Functions 可包裹 human approval、error handling 和 conditional routing。
合作/學習視窗

可服務不想被單一雲鎖定的客戶，提供雲外中立 runtime 證據層。

風險邊界

AWS 擁有采購、IAM 和工作流入口；ALUX 不能只講“也能審批”，要講跨系統長交易和審計證明。

今天的新變化

今天重點不再是 Web Search，而是 Identity、持久終端與 Step Functions 把 agent 納入雲工作流。

06Alibaba Qwen / Qwen Code中國/開源2026-07 觀察 / 2026-07-04官方 GitHub

Qwen Code 開源終端智慧體繼續升溫，Auto-Memory、Auto-Skills、SubAgents 與 MCP 進入中國開源開發棧

發生了什麼：Qwen Code 是終端內開源 AI coding agent，可讀寫檔案、執行命令並連線 MCP；生態文件強調 memory、skills、subagents、agent teams 和多模型協議。

對 ALUX 的關係：中國開源 Agent 工具鏈開始以終端、skills、memory、subagents、MCP 的方式複製 Codex/Claude Code 路線。ALUX 可利用這類開放生態做多模型 runtime 適配，不被美國模型廠商繫結。

可行動建議與產出物：建議建立中國 Agent authoring 框架適配清單：Qwen Code、Qwen-Agent、Kimi、MiniMax、DeepSeek。 中國 Agent authoring 適配清單。

RISC: I 主 · 智慧/大腦次維度 S
工具編排是Qwen Code 可直接編輯檔案、執行命令並連線 MCP。
記憶使用部分生態文件強調 Auto-Memory，但公開 GitHub 摘要未證明企業級記憶治理。
合作/學習視窗

可探索 Qwen Code / Qwen-Agent 作為 ALUX 上層 authoring 的中國生態入口。

風險邊界

開源終端 agent 越易普及，越會放大本地檔案、命令和憑據風險；ALUX 不能忽視開發者安全體驗。

今天的新變化

延續 7 月 3 日觀察；今天保留為中國 Agent 開源供給側的核心樣本。

07NVIDIA NeMo美國/全球2026-07-04 觀察 / 2026-07-04官方產品頁

NVIDIA NeMo 把 agent 生命週期包裝為 build、monitor、optimize、guardrails 與 observability

發生了什麼：NeMo 明確面向 agentic AI，覆蓋資料、後訓練、評估、guardrails、observability、持續最佳化和安全生產部署。

對 ALUX 的關係：NVIDIA 作為算力和企業軟體入口，正在把 agent lifecycle 包成生產套件。ALUX 應學習它的 lifecycle 語言，但保留“執行時證據、能力授予、跨公司協作”的差異。

可行動建議與產出物：建議形成“Agent lifecycle 缺失的 runtime proof layer”圖，區分評估/護欄/觀測與可重放執行證據。 runtime proof layer 生命週期圖。

RISC: S 主 · 安全/免疫次維度 I
策略審批是NeMo 頁面明確包含 guardrails、policy enforcement 和安全部署。
回滾審計部分頁面強調 observability 和 monitoring，但未證明逐步回滾或重放審計。
合作/學習視窗

可將 ALUX 作為 NeMo/模型訓練棧之後的執行與審計層，面向企業安全、AIOps 和合規團隊。

風險邊界

NVIDIA 生態會強化從訓練、評估到部署的垂直閉環；ALUX 要避免被看成另一個 observability 外掛。

今天的新變化

08Kong AI Gateway / Langflow / Dify美國/安全生態2026-07-02 / 2026-07-04公司安全部落格

Kong 把 Langflow / Dify 漏洞串成 AI Agent Gateway 需求，強調 compromised agent 的行動半徑大於普通 Web 表單

發生了什麼：Kong 文章將 Langflow RCE、Dify 跨租戶資料暴露等風險歸為結構性治理缺口，認為 agent 會帶著授權呼叫工具和觸發工作流，攻擊半徑更大。

對 ALUX 的關係：Kong 把 agent compromise 的 blast radius 講清楚：Agent 不只洩露資料，還會帶著許可權行動。ALUX 可把這類 gateway 安全敘事推進一步，強調工具呼叫之後的長交易狀態、能力衰減和可重放追責。

可行動建議與產出物：建議把 Runtime vs Gateway 對比頁升級為銷售資產：閘道器攔截請求，ALUX 記錄授權、狀態轉移和回放證據。 Runtime vs Gateway 銷售對比頁。

RISC: S 主 · 安全/免疫次維度 C
隔離邊界是文章指出 Dify 跨租戶資料暴露和內部 API 未授權訪問，隔離失敗是核心風險。
策略審批部分Kong 主張 gateway 治理層，但文章不是具體策略審批產品說明。
合作/學習視窗

可和 API gateway / IAM / security vendors 合作，讓 ALUX trace 成為它們攔截之後的證據層。

風險邊界

Kong 等閘道器廠商會搶“Agent 安全入口”預算；ALUX 必須說明 gateway 管流量，ALUX 管長交易執行與證明。

今天的新變化

今天觀察到該訊號與生產級執行時敘事的關係更清晰。

融資 / 合作視窗

最直接視窗：企業安全閘道器、雲工作流、Agent observability、終端編碼智慧體、中國開源模型生態。它們都在處理同一件事：Agent 開始攜帶許可權、狀態和組織上下文行動。
融資敘事視窗：把 OpenAI 的工時研究、Claude Tag 的團隊會話、MAF 的 durable worker、AWS 的 Identity/Step Functions 和 Kong 的漏洞敘事串起來，說明執行時責任鏈正在成為獨立市場。

技術 / 產品啟發

優先產品：RISC scorecard demo。每個 demo action 都給出主維度、兩條證據、能力物件、狀態推進、恢復點和回放判定。
優先 Demo：Slack/終端/雲工作流混合長交易：團隊頻道發起、終端執行、Step Functions 審批、失敗補償、審計回放。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。準確說，當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。

也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。
