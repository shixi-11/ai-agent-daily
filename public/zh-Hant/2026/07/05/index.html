RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

01Kong AI Gateway / Langflow / Dify美國/安全生態2026-07-03公司安全部落格

Kong 將 Langflow、Dify 漏洞歸納為 AI Agent Gateway 缺口：被攻陷的 agent 會帶著授權繼續行動

發生了什麼：Kong 文章把 DifyTap、Langflow RCE 和多租戶隔離風險串成 agent gateway 需求，強調 agent 平臺裡的憑據、工具和工作流讓攻擊半徑大於普通 Web 應用。

對 ALUX 的關係：Kong 把 Langflow 與 Dify 的漏洞從單點 bug 提煉成 agent 平臺治理缺口，正好驗證 ALUX 的安全免疫敘事：智慧體一旦帶著工具和憑據行動，許可權邊界、隔離、可審計證據就不再是附加功能。

可行動建議與產出物：建議形成一頁 Agent Platform Attack Surface 圖，把網頁內容、RAG、憑據、工具執行和審計缺口放在同一條鏈上。

RISC：S 主 · 安全 / 免疫R 輔 · 強韌 / 機體
隔離邊界是來源明確討論 Dify 跨租戶暴露和 Langflow 平臺邊界失守。
策略審批部分文章主張 gateway 與治理，但未證明逐操作審批已覆蓋所有平臺。
合作/學習視窗

適合與 agent gateway、API gateway、安全諮詢和紅隊團隊對話，形成 Runtime Threat Model 聯合材料。

風險邊界

風險是 gateway 廠商會把免疫系統講成流量層安全，ALUX 必須明確自己管的是跨步驟狀態、能力授予和事後證明。

今天的新變化

這是 7 月初的新安全敘事，把孤立漏洞上升為 agent 平臺治理缺口。

02Amazon Bedrock AgentCore美國/全球雲平臺2026-06官方文件

Amazon Bedrock AgentCore June notes：Guardrails、Gateway、Runtime、Payments 與 persistent terminals 合流

發生了什麼：AgentCore release notes 顯示 Guardrails 可在 gateway 層執行，runtime targets、HTTP passthrough、source validation、payments、persistent terminals 和 Step Functions harness 進入同一產品線。

對 ALUX 的關係：AgentCore 說明雲廠商正在把 agent 從模型呼叫推到雲內工作負載控制面。ALUX 要借這個趨勢解釋：雲 gateway 適合自家雲，ALUX 的機會是中立、跨公司、可重放的長交易執行時。

可行動建議與產出物：建議補一頁 Runtime vs Cloud Gateway：雲閘道器守入口，ALUX 記錄跨系統狀態、授權路徑和可重放證據。

RISC：C 主 · 連線 / 社會S 輔 · 安全 / 免疫
生態連線是release notes 包含 HTTP passthrough、runtime targets、MCP、payments、Step Functions 和知識庫連線。
會話型別是文件提到 MCP sessions、session stickiness、budget-limited session 和 persistent terminal state。
合作/學習視窗

可面向雲安全、支付 API、MCP server 供應商做互補敘事：ALUX 提供跨雲和跨組織證據層。

風險邊界

AWS 的雲內閉環會壓縮普通 runtime 敘事；ALUX 需要避免只講“閘道器”，轉而講中立基底和跨公司責任鏈。

今天的新變化

今天重新核驗官方文件，重點轉向 gateway 防繞過、payment session 與 persistent terminal 共同形成雲內 agent 控制面。

03Langflow / JADEPUFFER全球安全2026-07-02可靠安全媒體

The Hacker News 報道 JADEPUFFER 利用 Langflow RCE 自動化資料庫偵察，AI 工具暴露開始被規模化利用

發生了什麼：報道指出攻擊者利用 Langflow 已修復的缺失認證 RCE，自動化資料庫發現和憑據濫用；Langflow 常儲存 API key 與雲憑據，成為高價值入口。

對 ALUX 的關係：這條把“AI agent 安全”從理論變成攻擊者行為。ALUX 的安全敘事要強調：模型之外的工具鏈、憑據、資料庫訪問和環境輸入都必須進入可審計執行時。

可行動建議與產出物：建議沉澱一個 Langflow-style exploit replay 示例，展示攻擊前後哪些環境輸入和工具動作需要被記錄。

RISC：S 主 · 安全 / 免疫R 輔 · 強韌 / 機體
隔離邊界是報道強調 Langflow 暴露服務可被缺失認證 RCE 進入，並觸達資料庫與憑據。
回滾審計部分報道描述攻擊行為，但沒有平臺級回放或追責機制。
合作/學習視窗

適合對接安全媒體、雲安全公司和開源 agent 平臺維護者，建立漏洞覆盤和執行時證據格式。

風險邊界

不能誇大成所有 Langflow 部署都被攻破；要準確說是已修復漏洞被暴露部署利用，結構風險在於 agent 平臺常存高許可權憑據。

今天的新變化

與 Kong 的治理敘事互相印證，但這裡提供了被利用鏈路和攻擊者行為樣本。

融資 / 合作視窗

最直接視窗：Agent gateway、安全諮詢、雲安全、沙箱、可觀測性和開源 coding agent 生態。它們正在處理同一個問題：智慧體一旦拿到憑據和工具，執行時必須能限制、記錄、恢復和證明。
融資敘事視窗：把 Kong/Langflow、AWS AgentCore、E2B、NVIDIA NeMo、Langfuse 和 Qwen Code 串成一條線：企業不是缺一個更會說話的模型，而是缺能讓智慧體可靠上線的機器。

技術 / 產品啟發

優先產品：Agent Platform Attack Surface。圖中至少包含網頁/RAG 輸入、模型輸出、能力授予、工具動作、沙箱邊界、外部 API、狀態轉移、checkpoint、審計回放。
優先 Demo：Sandbox Payment 長交易：agent 在隔離環境裡報價、請求預算、呼叫支付聯結器、遇到失敗後補償，並輸出可重放審計證據。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。準確說，當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。

也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。
