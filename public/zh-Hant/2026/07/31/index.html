今天的新變化

今天的新變化是 LangGraph 將檢查點隔離問題定位到名稱空間段邊界，並同時修復 PostgreSQL 與 SQLite 儲存。

LiteLLM 1.95 RC 為全部 Docker 映象加入 Cosign 簽名

發生了什麼：1.95.0 RC 宣佈所有 LiteLLM Docker 映象使用 Cosign 和穩定釋出金鑰簽名，讓部署方可以在拉取 Agent 模型閘道器前驗證製品來源。

對 ALUX 的關係：模型閘道器位於 Agent 許可權與資料路徑的中心，製品來源必須先可信，執行記錄才有意義。ALUX 可把映象簽名驗證結果繫結到程式碼版本、能力集合和重放收據。

可行動建議與產出物：建議形成 Signed Runtime Artifact Receipt v0，記錄 image_digest、signature_identity、verification_time、config_hash 與 capability_set。 可沉澱為：Signed Runtime Artifact Receipt v0。

RISC：S 主 · 安全 / 免疫R 輔 · 強韌 / 機體

這條訊息主要動到機器人的安全 / 免疫：Agent 模型閘道器的部署製品必須驗證來源；強韌 / 機體為輔，因為可恢復執行需要明確知道恢復到哪一個可信版本。

隔離邊界部分映象簽名建立製品來源邊界，但不等於執行時沙箱或租戶隔離。
回滾審計部分Cosign 可驗證映象來源和 digest，未證明執行過程或效果可重放。
合作 / 學習視窗

可將 LiteLLM 作為多模型閘道器適配層，驗證 signed artifact 到 runtime capability 的鏈路。 學習其把容器簽名作為每次釋出的預設供應鏈合同。

風險邊界

這是候選版本；映象簽名證明發布來源，不證明映象無漏洞、執行配置安全、金鑰未濫用或請求執行可重放。

今天的新變化

今天的新變化是 LiteLLM 將 Cosign 簽名從可選做法提升為全部 Docker 釋出製品的統一合同。

融資 / 合作視窗

最直接合作面：Microsoft Agent Framework 是恢復與人工審批對照；CrewAI、Deep Agents、Google ADK、Kimi Code 和 LangGraph 是框架適配入口；Phoenix 是觀測出口，LiteLLM 是多模型閘道器與製品驗證入口。
資本敘事：今天沒有可驗證的新融資金額值得進入正文。更強的結構訊號是，頭部框架正在為恢復、失敗、信任、認證、外掛來源、狀態隔離和製品供應鏈分別補責任欄位；ALUX 的位置是把這些欄位合成可驗證的生產級執行時協議。

技術 / 產品啟發

優先產品：Agent Recovery Responsibility Envelope v0。建議欄位：execution_id、initial_input_hash、human_response_ref、capability_set、artifact_digest、checkpoint_ref、effect_cursor、terminal_verdict、replay_ref。
優先 Demo：讓 Microsoft Agent Framework 工作流在人工審批後中斷，恢復時同時校驗 LiteLLM 映象簽名、LangGraph 狀態名稱空間和 Google ADK 呼叫能力；子 Agent 經 Kimi 外掛委派，CrewAI 工具失敗必須形成真實終態，Phoenix 只負責展示 trace，ALUX receipt 負責證明狀態和效果。

風險邊界

ALUX 仍不能被描述為已經完整交付的智慧體平臺。底層 TVM 已具備原生併發、持久執行、能力安全、執行記錄與逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤和評估工具仍待構建與融資。TVM 不會讓 LLM 本身確定性；它記錄模型輸出與環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。框架檢查點、失敗事件、工作區信任、A2A 認證頭、外掛 manifest、名稱空間修復、trace 計數或映象簽名，都不能單獨證明外部效果冪等、跨步驟原子回滾、不可偽造能力和中立跨公司協作。
