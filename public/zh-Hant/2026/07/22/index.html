RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

這條訊息主要動到機器人的智慧 / 大腦：瀏覽工具編排和模型端點選擇構成任務執行迴圈；安全 / 免疫為次維度，因為軌跡需要成為可核查證據而非普通日誌。

工具編排是Stagehand 以瀏覽器動作軌跡為核心，並新增按執行歸組。
模型迴圈部分支援 OpenAI Chat Completions 相容端點，但版本說明未展開完整自主迴圈。
合作/學習視窗

可做 Stagehand Browser Effect Adapter，把導航、點選、表單與最終頁面狀態寫入 ALUX effect receipt。 學習 Stagehand 如何把瀏覽軌跡與外部評估實驗對齊，並保持模型端點可替換。

風險邊界

軌跡歸組和實驗連結不等於確定性重放；OpenAI 相容端點只表示協議相容，不證明所有模型行為一致。

今天的新變化

3.7.4 首次把軌跡按執行歸組、Braintrust 實驗連結與 OpenAI 相容端點放入同一版本。

融資 / 合作視窗

最直接視窗：Microsoft Agent Framework 適合做型別化會話與多協議入口；Codex 可驗證跨產品工作狀態遷移；Pydantic AI 提供 durability adapter 入口；Claude Code、Qwen Code、Kimi Code 與 Stagehand 分別提供恢復、並行執行域、許可權傳播和瀏覽效果樣本。
融資敘事視窗：今天沒有新的可靠融資金額進入正文。更值得強調的是，模型與框架公司正在分別為跨會話來源、執行緒遷移、持久化後端、轉錄完整性和許可權傳播付出工程成本；ALUX 的機會是把這些碎片收進統一生產執行時。

技術 / 產品啟發

優先產品：Agent Session Provenance Envelope v0。欄位建議包括 session_id、origin、owner、thread_lineage、memory_scope、connector_epoch、runtime_model、permission_epoch、transcript_commit、effect_cursor 與 recovery_verdict。
優先 Demo：從 Codex 匯入一份帶 MCP 與子 Agent 的工作狀態，透過 Microsoft Agent Framework 接收人工 response URL，再用 Qwen worktree 和 Stagehand 完成外部動作；中途切換許可權並重啟執行器，展示 ALUX 如何恢復原狀態、衰減能力並證明最終效果。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。跨會話來源、執行緒匯入、durability adapter、轉錄警告、許可權傳播與瀏覽軌跡都不能自動證明跨步驟原子回滾、物件能力或中立跨公司協作。
