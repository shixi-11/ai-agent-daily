RISC 机器说明

RISC = 生产级 Agent / 机器人身体的四个系统

一个真正能上生产的 Agent，不能只有大脑。它要能持续运行，要能判断和行动，要能抵御错误、攻击和投毒，也要能进入真实世界的协作网络。

行业已经交付了一颗出色的大脑，但生产级 Agent 还需要机体、免疫和社会。ALUX 构建的，就是这台完整机器。
R｜强韧 / 机体容错、持久执行、故障切换、水平扩展。没有强韧机体，一次崩溃就会带走全部工作。
I｜智能 / 大脑推理循环、记忆、工具调用、任务编排。这是今天所有 Agent 框架最拥挤、也最成熟的竞争层。
S｜安全 / 免疫对象能力、策略约束、回滚机制、审计链路。没有安全免疫，一条被投毒的指令就可能造成真实损害。
C｜连接 / 社会跨公司授权、中立基底、会话类型、协作边界。没有连接网络，每家公司的 Agent 都只能困在自己的孤岛里。

可行动建议与产出物：建议形成 Toolset Epoch Receipt，记录 turn_id、toolset_digest、tool_change、grant_source、fallback_route 与 approval_ref。 可沉淀为：Toolset Epoch Receipt v0。

RISC：I 主 · 智能 / 大脑S 辅 · 安全 / 免疫

这条消息主要动到机器人的智能 / 大脑：模型回路中的可用工具集合可以动态变化；安全 / 免疫为次维度，因为工具授予、撤销与 fallback 路由必须可追责。

工具编排是官方 SDK 新增工具添加/移除 block 与 tool_change 事件。
模型循环是工具集合变化成为模型 API 的正式事件，可进入后续回合处理。
合作/学习窗口

可构建 Anthropic Toolset Epoch Adapter，把 tool_change 事件映射为能力授予、撤销与回合级工具集摘要。 学习模型 API 如何把工具集合变化显式化为流事件，而不是隐含配置变化。

风险边界

事件可见不等于权限安全；SDK 没有证明工具增删来源经过策略审批，也没有证明 fallback 不会改变模型行为与证据边界。

今天的新变化

0.120.0 首次把工具增删与 tool_change 事件写入官方 Python SDK。

融资 / 合作窗口

最直接窗口：Claude Code 提供网络与审批样本；Agno 与 Qwen Code 提供持久状态和 runtime epoch；E2B、CrewAI、Kimi Code、Strands 与 Anthropic SDK 提供路径、终态、超时、取消和工具变更样本。
融资叙事窗口：今天没有新的可靠融资金额进入正文。更有力的资本信号是：框架公司正在分别为“状态恢复时权限是否仍然正确”付出工程成本；ALUX 的差异是把策略、状态和效果证明收进统一生产运行时。

技术 / 产品启发

优先产品：Policy-Carrying Agent Run Envelope v0。字段建议包括 state_ref、capability_set、network_policy、toolset_epoch、model_binding、approval_ref、runtime_epoch、recovery_verdict、effect_cursor 与 evidence_refs。
优先 Demo：让 Claude Code 的三级子 Agent 通过 Kimi / Strands 路由模型并调用 MCP 工具，把中间文件写入 Agno 状态层、在 E2B 解析软链接；中途撤销网络主机、改变工具集并重启 Qwen daemon，展示 ALUX 如何恢复状态而不恢复过期权限。

风险边界

ALUX 不能被说成已经完整交付智能体平台。当前底层 TVM 已具备并发、持久化执行、能力安全、运行记录和逐比特重放审计等关键基础；智能体产品层、可观测性、仪表盘、追踪与评估工具仍是待构建和融资重点。也不要说 TVM 让 LLM 本身确定性。准确说，TVM 记录模型输出和运行环境输入，使编排、权限、状态转移和审计可重放、可验证。默认拒绝网络、持久文件、runtime epoch、软链接可见性、失败终态、MCP 超时、调用取消和 tool_change 事件都不能自动证明对象能力、外部效果回滚、端到端证据完整性或中立跨公司协作。
