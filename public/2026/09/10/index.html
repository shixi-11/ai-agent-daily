RISC机器说明

RISC = 生产级 Agent / 机器人身体的四个系统

一个真正能上生产的 Agent，不能只有大脑。它还要持续行动、扛住故障、抵御越权，并进入真实组织协作。

行业已经交付了一颗出色的大脑，但生产级 Agent 还需要机体、免疫和社会。ALUX 构建的，就是这台完整机器。
R｜强韧 / 机体持久执行、容错、恢复与水平扩展。身体站不住，一次故障就会把工作清空。
I｜智能 / 大脑模型循环、记忆、工具与编排。它决定 Agent 如何思考、调用和完成复杂工作。
S｜安全 / 免疫能力对象、策略审批、回滚与审计。没有免疫，恢复与连接会扩大失控半径。
C｜连接 / 社会跨公司授权、中立基底、会话类型与生态连接。没有社会接口，Agent 只能停在单一产品里。

01OpenAI ChatGPT Images 2.5United States / Global2026-09-08 发布 / 2026-09-10 观察官方发布

ChatGPT Images 2.5 更懂草图与参考照

发生了什么：OpenAI 发布 ChatGPT Images 2.5，官方称新版能把文字想法、手绘草图和参考照片转成更贴近用户意图的成品，并强化个性化与画面完成度。它把“先给轮廓、再让模型补足视觉语言”推到更直接的产品入口。

为什么值得关注：图像 Agent 的竞争点正从单轮生成，转向能否理解不完整意图并稳定保留参考关系。草图和照片若能共同成为约束，创意沟通会少一次语言转译。

适合谁看：品牌设计、广告创意、商品视觉、内容团队和多模态产品负责人。

试试看

用同一张粗略草图配三组不同参考照，固定主体与版式，只改变材质和气氛，比较人物、文字与空间关系是否漂移。

注意点

功能描述来自 OpenAI 官方 RSS 与产品页摘要；本期未独立测试提示词遵循、中文文字准确率、价格、速度或多轮编辑一致性。

02OpenAI Navier–Stokes ResearchUnited States / Global research2026-09-08 发布 / 2026-09-10 观察官方研究

OpenAI 提交 Navier–Stokes 解答与 Lean 证明

发生了什么：OpenAI 公布一份由 AI 生成的 Navier–Stokes 千年难题解答，同时提供论文式说明与 Lean 形式化证明。公开材料把自然语言论证和机器可检查对象放在一起，让外部研究者能够分别检查数学主张与形式化链条。

为什么值得关注：科研 Agent 的高价值输出正在从“看起来像证明”走向可被证明助手逐步验证的对象。若这套模式成立，同行评议会多出一条可重放、可定位错误的检查通道。

适合谁看：数学研究、形式化验证、科研 Agent、证明助手与高可信软件团队。

试试看

先确认 Lean 工程能完整编译，再随机抽取三个关键引理，对照论文陈述、形式定义和依赖关系，最后检查是否存在未声明公理。

注意点

OpenAI 官方称其为 AI 生成的解答并公开 Lean 证明；本期没有独立复核整套数学论证，也不能把发布等同于学界或千禧年奖项机构已认可。

03OpenAI Codex Quantum ExperimentsUnited States / Global research2026-09-08 发布 / 2026-09-10 观察官方研究

Codex 进入量子实验的闭环校准

发生了什么：OpenAI 介绍一项 MIT 研究实践：研究者用 GPT-5.6 Sol 与 Codex 自主运行量子计算实验、分析结果并校准量子比特。Agent 不只生成实验代码，还在观测数据返回后继续调整下一轮操作，形成工具调用与物理反馈闭环。

为什么值得关注：当模型能读取仪器反馈并修改下一步，实验 Agent 的核心就不再是写脚本，而是受约束地循环执行、判断异常、保存状态并在人类设定的边界内恢复。

适合谁看：量子计算、实验室自动化、科研平台、仪器软件与长流程 Agent 团队。

试试看

把案例拆成计划、执行、测量、诊断和校准五段，逐段标出允许自动继续的条件、人工批准点以及异常时必须停止的阈值。

注意点

流程由 OpenAI 官方案例描述；本期未接触实验设备或原始数据，无法独立评估成功率、实验成本、可复现性和人工介入程度。

04Tencent EVIEChina / Global open source2026-09-04 发布 / 2026-09-10 观察官方开源发布

腾讯 EVIE 开源视觉文档检索双模型

发生了什么：腾讯开源 EVIE-8B 与 EVIE-4.5B，用逐词元多向量和 MaxSim 做视觉文档检索，保留版式、字体、图表及表格关系。官方模型卡称 8B 版在 ViDoRe V3 达到 66.75 nDCG@10，并同步提供权重、推理与评测代码。

为什么值得关注：文档 Agent 若先把整页压成单一向量，容易丢掉局部结构。多向量后期交互让查询能对准页面片段，为合同、财报和知识库检索提供更细的证据入口。

适合谁看：企业搜索、RAG、合同与财报处理、知识库以及多模态检索团队。

试试看

选取含双栏、跨页表格和小字号脚注的文档集，对比单向量基线与 EVIE 的召回结果，并记录显存、索引体积和查询延迟。

注意点

Apache-2.0 权重与代码已公开；66.75 为官方模型卡在指定评测流程中的结果，本期未复现，也不代表所有语言和企业文档都同样领先。

05OpenAI Agents SDK for PythonUnited States / Global open source2026-09-08 发布 / 2026-09-10 观察官方开源发布

OpenAI Agents SDK 把护栏推到 MCP 服务器层

发生了什么：OpenAI Agents SDK for Python v0.22.1 为 MCP 工具增加服务器级统一护栏，并加入可配置的 Unix 本地环境隔离、Docker 容器标签、网页搜索图片结果及流式语音转写选项。版本同时修复空工具参数与审批恢复等边界行为。

为什么值得关注：工具越多，逐个调用点补安全规则越容易漏。把护栏上提到 MCP 服务器层，可以让同一能力入口共享检查策略，并让隔离与审计边界更清楚。

适合谁看：Agent 平台、MCP 服务、开发自动化、安全工程和语音工作流团队。

试试看

给测试 MCP 服务器设置统一拒绝规则，再从两个不同 Agent 调用同一工具，验证拦截信息、追踪记录、恢复流程和本地隔离配置。

注意点

功能和修复项来自官方 v0.22.1 发布记录；本期未做跨平台沙箱逃逸测试，也不能把进程环境隔离等同于完整安全沙箱。

06OpenAI SymphonyUnited States / Global open source2026-09-09 发布 / 2026-09-10 观察官方开源发布GitHub Stars 27,124许可证 Apache-2.0

OpenAI Symphony 把任务板变成隔离实现队列

发生了什么：OpenAI 公开 Symphony 工程预览：它监看 Linear 等项目任务，为每项工作创建隔离的自主实现运行，并把 CI、代码审查、复杂度分析和演示视频作为交付证据；仓库同时提供规范与 Elixir 参考实现。

为什么值得关注：编码 Agent 的管理单位从一次对话转向工作项。隔离运行、验收证据和落地前审批若成为默认，团队可以管理结果，而不是逐步盯着模型操作。

适合谁看：研发管理、编码 Agent 平台、DevOps、代码审查与长流程自动化团队。

试试看

先在无敏感数据的测试仓库接入一类低风险任务，要求每次运行提交 CI、审查意见和变更演示，再检查失败隔离与人工接受路径。

注意点

Apache-2.0 代码、规范与参考实现已公开，但官方明确称其为可信环境下的低调工程预览；本期未验证生产稳定性、权限隔离或自动合并安全。

GitHub开源发现

Stars为成稿时的关注度快照，不代表质量排名。许可证按官方仓库准确标注。

14Split-LLM Privacy StudyEurope / Global research2026-09-03 发布 / 2026-09-10 观察官方研究

Split-LLM 返回梯度会暴露真实样本行

发生了什么：研究发现，Split-LLM 训练返回的梯度零模式会区分真实行与诱饵行，并在作者实验的九个种子中全部命中。

为什么值得关注：前向表示做了伪装，不代表反向更新不会泄露同一秘密。

适合谁看：隐私训练、联邦学习与企业模型平台团队。

试试看

用合成数据复现实验，再分别测试裁剪、加噪和不同批量。

注意点

结果覆盖作者设定的威胁模型；另有五类攻击未测，不能外推所有 Split-LLM。

本期观察：模型接口继续变宽，但生产差异越来越落在状态、证据与权限能否被长期保留和独立验证。
