RISC机器说明

RISC = 生产级 Agent / 机器人身体的四个系统

一个真正能上生产的 Agent，不能只有大脑。它还要持续行动、扛住故障、抵御越权，并进入真实组织协作。

行业已经交付了一颗出色的大脑，但生产级 Agent 还需要机体、免疫和社会。ALUX 构建的，就是这台完整机器。
R｜强韧 / 机体持久执行、容错、恢复与水平扩展。身体站不住，一次故障就会把工作清空。
I｜智能 / 大脑模型循环、记忆、工具与编排。它决定 Agent 如何思考、调用和完成复杂工作。
S｜安全 / 免疫能力对象、策略审批、回滚与审计。没有免疫，恢复与连接会扩大失控半径。
C｜连接 / 社会跨公司授权、中立基底、会话类型与生态连接。没有社会接口，Agent 只能停在单一产品里。

01Stable Audio 3 Optimized英国 / 全球音频开发者2026-05-18 发布 / 2026-08-30 观察官方模型更新

Stable Audio 3 撤下校准错误的 FP8 引擎

发生了什么：Stability AI 在优化权重页撤下校准错误的 SM120 FP8 编码器与已过时的 SM90 引擎，把旧 ONNX 移入 legacy，并发布带限幅器、固定输出上限和重新校准激活尺度的可构建 ONNX。模型本体并非今日首发，变化发生在 8 月 27—28 日的部署制品层。

为什么值得关注：本地生成模型的风险不只来自权重；错误量化尺度和过时引擎会把音质、削波与复现偏差带进整条生产链。

适合谁看：部署 Stable Audio 3、ONNX、TensorRT 或 FP8 音频生成的团队。

试试看

先锁定文件哈希，再用同一批提示比较新版与 legacy 引擎的峰值、削波、响度和生成耗时，确认回退路径可用。

注意点

优化仓库明确标为实验制品，使用 Stability AI Community License；硬件特定加速结果不能直接外推到所有设备或商业场景。

02MiniMax CLI中国 / 全球多模态开发者2026-08-21 发布 / 2026-08-30 观察官方开源发布GitHub Stars 2,076许可证未声明

MiniMax CLI 1.0.21 给 H3 Skill 加上超时边界

发生了什么：MiniMax CLI 1.0.21 为 H3 视频生成补上独立 Agent Skill，并加固视频 SDK、停滞流超时与资源下载上限；语音合成增加情绪、文本规范化和 LaTeX 朗读参数，同时下线已经不再符合当前 API 的 Music CLI 与 SDK。

为什么值得关注：多模态工具一旦进入 Agent，长时生成、下载体积与能力退役都需要明确合同，不能只靠命令能否启动。

适合谁看：用 OpenClaw、Codex、Claude Code 或终端编排 MiniMax 多模态能力的团队。

试试看

在无敏感素材的测试任务里调用 H3 Skill，分别制造超时与超限下载，核对错误、清理、重试和能力列表。

注意点

版本发布于 8 月 21 日，今天是补抓；它依赖 MiniMax Token Plan，且 Music CLI 已退役，不能按旧命令假设能力仍在。

GitHub开源发现

Stars为成稿时的关注度快照，不代表质量排名。许可证按官方仓库与模型卡准确标注。

03Pydantic AI全球 / 开源开发者2026-08-29 发布 / 2026-08-30 观察官方开源发布GitHub Stars 19,579许可证 MIT

Pydantic AI 2.36 开放持久操作后端接口

发生了什么：Pydantic AI 2.36 新增 `@durable_operation`，要求每个持久操作显式命名，并开放第三方持久执行引擎可实现的公共后端 API；同时给 instruction part 增加稳定 ID，为 clai 补上 MCP 配置与工具调用流式输出。

为什么值得关注：长流程开始把“哪一步可恢复、由谁接管、怎样避免重复执行”写进框架接口，而不是留给业务层临时拼接。

适合谁看：使用 Temporal、Prefect 或自研引擎承载长时 Agent 工作流的团队。

试试看

把一个可撤销外部调用标成持久操作，模拟进程中断与重复投递，检查操作名、缓存键、恢复位置和副作用是否一致。

注意点

公共后端 API 只提供接点，不自动保证外部服务幂等、补偿事务或跨引擎语义一致；接入前仍需故障测试。

04OpenAI Codex美国 / 全球开发者2026-08-29 发布 / 2026-08-30 观察官方开源发布GitHub Stars 119,808许可证 Apache-2.0

Codex 0.151 允许扩展改写 MCP 工具结果

发生了什么：Codex 0.151 让扩展在 MCP 工具结果进入模型前检查或替换内容，并为可选 MCP 服务增加可配置发现宽限期。版本还保留恢复后的权限配置，阻止 `/cd` 弱化沙箱，按真实执行器系统与路径强制远程隔离，并把子 Agent token 计入根目标预算。

为什么值得关注：工具结果第一次进入可编程检查点，但这也把新的信任边界放到扩展层；预算、权限和结果变换必须一起审计。

适合谁看：维护 Codex、MCP 扩展、远程沙箱和多 Agent 预算控制的团队。

试试看

写一个只脱敏测试字段的结果处理扩展，再恢复旧会话并切换目录，检查输出、权限配置、沙箱范围与根预算。

注意点

扩展可替换工具结果，意味着扩展本身也能改变模型证据；应限定来源、版本与权限，并保留原始结果供审计。

05Microsoft AI Audio Descriptions美国 / 无障碍技术2026-08-29 发布 / 2026-08-30 观察官方仓库更新GitHub Stars 49许可证 MIT

Microsoft 把音频描述重写成人工可编辑流水线

发生了什么：Microsoft 在 8 月 29 日重写 AI Audio Descriptions：系统分析 MP4、找出对白间隙并生成 WebVTT 草稿，由编辑者修改后再用语音合成、压低原声并混成新视频。新架构以 Python 引擎统一 Studio 与 CLI，原生 FFmpeg 渲染移到服务端。

为什么值得关注：这是很清楚的人机接力样本：AI 负责结构化初稿，人保留叙事判断，渲染链只消费已经审过的中间文件。

适合谁看：做无障碍媒体、视频本地化、编辑工具和人机协作工作流的团队。

试试看

用一段自有短视频生成 WebVTT，只比较时隙、叙述准确性和混音，不直接发布；记录每次人工改动与最终渲染差异。

注意点

当前版本是单机本地文件方案，没有认证、多机协调或共享云存储；README 明确要求未补安全控制前只绑定本机回环地址。

06THUDM slime中国 / 全球训练设施2026-08-28 发布 / 2026-08-30 观察官方开源发布GitHub Stars 8,306许可证 Apache-2.0

slime 0.3.2 对齐 GLM-5 训练与推理回放

发生了什么：THUDM 发布 slime 0.3.2，为 GLM-5 打通 Megatron 训练与 SGLang rollout 的确定性对齐，覆盖 DeepEP、DSA 稀疏注意力和 FP8 KV 缓存；同时修复异步 rollout 丢组、工具调用分词与 PPO/OPD 统计，并提供 CUDA 13 环境。

为什么值得关注：强化学习后训练若训练侧与 rollout 侧不能逐项对齐，奖励、梯度和评测会在规模化时悄悄漂移。

适合谁看：运行 GLM-5、SGLang、Megatron、异步 RL 与 Blackwell 训练集群的团队。

试试看

选一组固定样本比较训练与 rollout 的 token、logprob、KV 精度和工具响应边界，再故意中断异步组检查是否丢失。

注意点

官方称大规模 GLM-5.3 负载已验证，但没有公开完整硬件、规模和复现实验；其他模型仍需自行建立对齐基线。

07Hugging Face timm全球 / 视觉开发者2026-08-28 发布 / 2026-08-30 观察官方开源发布GitHub Stars 37,109许可证 Apache-2.0

timm 1.0.29 加入 LowFormer 与 Agent 发现的修复

发生了什么：Hugging Face 发布 timm 1.0.29，新增 LowFormer 定义与预训练权重，并合入一批由 Agent 暴露的真实但低频缺陷修复；同一版本还补齐 NaFlex 训练、位置插值缓存、CutMix、优化器、分类头设备与 dtype 等边界。

为什么值得关注：Agent 能扩大测试搜索面，但维护者仍需把发现收敛成可复现修复；这里出现了“机器找边角、人维护主干”的工程闭环。

适合谁看：维护视觉模型库、自动回归、边缘设备骨干网络与训练工具链的团队。

试试看

在固定环境加载 LowFormer，并挑一个与自身训练路径相关的修复做最小复现，比较升级前后的数值、设备与 dtype 行为。

注意点

发布说明没有逐项标明哪些缺陷由哪类 Agent 发现，也不证明自动发现结果天然正确；仍应查看对应 PR 与测试。

08LMDeploy中国 / 全球推理设施2026-08-19 发布 / 2026-08-30 观察官方开源发布GitHub Stars 8,033许可证 Apache-2.0

LMDeploy 0.16 重做 MoE 与多模态推理底座

发生了什么：LMDeploy 0.16 加入 Intern-S2 Mobius、GLM-5.2、Hy3、MTP 与 TurboMind ViT，补上 SM90 BF16/FP8 GEMM、SSM 前缀缓存和异步引导解码；还把分离式 P2P 请求改为 JSON，并修复 CUDA 流输入生命周期与 KV 量化范围。

为什么值得关注：推理底座正在同时承受 MoE、多模态、缓存、分离式部署和新硬件，接口与内存正确性比单点吞吐更难维护。

适合谁看：部署 InternLM、GLM、Qwen VL、MoE 与 Hopper/Blackwell 推理集群的团队。

试试看

用一组固定多模态请求对比 0.15 与 0.16 的缓存命中、首 token、显存和输出签名，再检查 P2P 消息是否仍可兼容。

注意点

版本覆盖面很大，单一基准不能证明所有后端都提升；CUDA 13、实验模型和分离式路径应按实际硬件分别验收。

09OpenAI and Cursor美国 / 编码 Agent 市场2026-08-28 发布 / 2026-08-30 观察官方公告

OpenAI 将停止向 SpaceX 收购后的 Cursor 供模

发生了什么：OpenAI 在官方公告中表示，Cursor 被 SpaceX 收购后，公司决定逐步结束向 Cursor 提供 OpenAI 模型的合同。公开 RSS 摘要确认了这一供应关系变化，但没有披露交易条款、完整过渡安排或具体停止日期。

为什么值得关注：编码 Agent 的产品连续性越来越取决于模型供应合同、所有权变化与多提供方切换能力，而不只是前端体验。

适合谁看：依赖单一模型供应商的编码 Agent、企业采购与平台架构团队。

试试看

盘点关键工作流对单一模型、配额和专有工具协议的依赖，演练一次不改用户数据的供应商切换与质量回归。

注意点

目前只采用 OpenAI 官方口径，不推断 SpaceX 与 Cursor 的交易细节，也不把合同收尾等同于服务已经立即中断。

本期观察：开源栈正在从“能跑”走向“能交付”。真正拉开差距的，是结果、状态、制品、训练回放与供应关系都有清楚的检查点和回退路。
