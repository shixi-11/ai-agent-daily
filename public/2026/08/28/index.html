RISC机器说明

RISC = 生产级 Agent / 机器人身体的四个系统

一个真正能上生产的 Agent，不能只有大脑。它还要持续行动、扛住故障、抵御越权，并进入真实组织协作。

行业已经交付了一颗出色的大脑，但生产级 Agent 还需要机体、免疫和社会。ALUX 构建的，就是这台完整机器。
R｜强韧 / 机体持久执行、容错、恢复与水平扩展。身体站不住，一次故障就会把工作清空。
I｜智能 / 大脑模型循环、记忆、工具与编排。它决定 Agent 如何思考、调用和完成复杂工作。
S｜安全 / 免疫能力对象、策略审批、回滚与审计。没有免疫，恢复与连接会扩大失控半径。
C｜连接 / 社会跨公司授权、中立基底、会话类型与生态连接。没有社会接口，Agent 只能停在单一产品里。

01Claude Code美国 / 全球开发者2026-08-27 发布 / 2026-08-28 观察官方发布

Claude Code 2.1.248 让受限模式成为硬边界

发生了什么：Anthropic 为 Claude Code 2.1.248 新增 --restricted：默认移除命令、代码执行和 WebFetch 工具，将文件工具限制在工作目录，拒绝 bypassPermissions，并忽略用户、项目和本地设置。版本还把跨会话消息扩至 Bedrock、Vertex 与 Foundry，并修复长会话缓存和凭据文件上传边界。

为什么值得关注：编码 Agent 开始提供可直接启用的低权限运行面，而不是只靠团队手写提示词约束工具。

适合谁看：在企业仓库、第三方模型网关或远程会话中运行 Claude Code 的团队。

试试看

在无敏感数据的测试仓库对比普通模式与 --restricted，逐项记录可见工具、可读路径、设置加载和跨会话消息行为。

注意点

受限模式仍保留工作目录内的文件工具，也允许显式加入 WebFetch；它缩小默认权限，但不替代容器、网络隔离、代码审查与组织策略。

02CrewAI美国 / 全球开发者2026-08-27 发布 / 2026-08-28 观察官方发布

CrewAI 1.15.18 把会话式 Flow 推入稳定版

发生了什么：CrewAI 1.15.18 将 conversational flows 提升为稳定能力，让声明式聊天 Flow 自带状态结构、路由响应格式与 crew 风格模型配置。版本同时修复空最终答案时工具结果丢失、会话角色错位、失败任务误记成功，以及恢复被抑制时缺少生命周期事件。

为什么值得关注：会话不再只是消息历史，而开始成为带类型状态、路由与终态证据的可编排工作单元。

适合谁看：用 CrewAI 构建客服、运营流程、长会话工作流和可观测 Agent 的团队。

试试看

先做一个两状态的脱敏聊天 Flow，分别触发正常结束、空答案和失败恢复，检查状态形状、角色与生命周期事件是否一致。

注意点

“稳定”是项目发布阶段声明，不等于所有并发、存储和外部工具组合都已生产验证；复杂 Flow 仍需故障注入与恢复测试。

03Amazon Bedrock India印度 / 数据驻留场景2026-08-27 发布 / 2026-08-28 观察官方公告

Amazon Bedrock 在印度境内运行 OpenAI 模型

发生了什么：AWS 为印度推出 OpenAI GPT-5.6 Terra 与 Luna 的地域推理配置，请求只在孟买和海得拉巴区域间调度。两款模型支持 100 万 token 上下文、文本与图像输入，并兼容 OpenAI Responses、Chat Completions 和 Bedrock Converse API；账单、配额与日志留在源区域。

为什么值得关注：模型接入正在从“能不能调用”转向“数据在哪处理、容量如何跨区调度、审计落在哪个控制面”。

适合谁看：服务印度金融、医疗、公共部门及其他数据驻留敏感场景的 Agent 团队。

试试看

用脱敏长文档分别调用 in. 地域配置与 global. 配置，对比路由范围、CloudTrail 记录、缓存命中和高峰吞吐。

注意点

印度地域配置不包含 Sol；被自动滥用检测标记的 GPT-5.6 内容可能被离线保留。数据驻留也不自动满足全部行业合规要求。

GitHub开源发现

Stars为成稿时的关注度快照，不代表质量排名。许可证按官方仓库与模型卡准确标注。

04Kimi Code中国 / 全球开发者2026-08-27 发布 / 2026-08-28 观察官方开源发布GitHub Stars 7,118许可证 MIT

Kimi Code 0.39 开启分叉子智能体与 Tower 编排

发生了什么：Moonshot AI 发布 Kimi Code 0.39.0：子 Agent 与 swarm 可选择携带调用方对话快照，新增实验性 Tower 多智能体编排和远程控制；前台 Bash 或子 Agent 也可在运行中转入后台。版本还限制远程终端只在 loopback 绑定下可用，并修复中断会话恢复崩溃。

为什么值得关注：多 Agent 协作开始把上下文继承、前后台切换、远程访问与恢复放进同一个会话生命周期。

适合谁看：使用 Kimi Code、ACP、子 Agent 和移动端远程查看编码任务的开发者。

试试看

在测试仓库分别启用 subagent_fork 与 Tower，只交付一个可撤销任务，记录对话继承、后台切换、恢复和终止后的真实状态。

注意点

Tower、分叉与远程控制均为实验功能，需要显式开关；会话快照会扩大上下文与敏感信息传播范围，远程访问也应保持最小暴露。

05Strands Agents美国 / 全球开发者2026-08-27 发布 / 2026-08-28 观察官方开源发布GitHub Stars 7,033许可证 Apache-2.0

Strands Agents 1.54 接上路由、取消与文件记忆

发生了什么：Strands Agents Python 1.54 与 TypeScript 1.15 同步加入可配置模型路由、Agent session_id、外部取消信号和 FileMemoryStore；TypeScript 还新增进程内任务引擎。版本修正缓存 token 计入上下文与压缩基线，并将取消信号继续传给 OpenAI 提供方。

为什么值得关注：路由、会话身份、持久记忆与取消必须共享同一运行语义，才能避免模型切换后留下失控任务或错误上下文。

适合谁看：维护多模型 Agent、长任务、文件记忆与跨语言 SDK 的平台团队。

试试看

建立两模型路由和 FileMemoryStore，在工具运行中注入取消，再检查会话 ID、缓存计数、记忆落盘与提供方是否同时停止。

注意点

外部取消信号与文件记忆只是基础接口，不自动提供分布式事务、加密、跨进程一致性或崩溃后的完整恢复。

06Microsoft SQuadGen中美 / 3D 研究2026-08-27 发布 / 2026-08-28 观察官方模型与代码GitHub Stars 0许可证 MIT

Microsoft 开放 SQuadGen 3D 四边形布局模型

发生了什么：微软亚洲研究院与清华团队开放 SQuadGen 的 MIT 权重、配置和推理代码。系统用 Chart Distance Fields 表示 3D 表面的四边形布局，组合约 107M 的 Geometry-AE、115M 的 SQ-VAE 与 802M 的扩散模型，从三角网格生成可供后续建模和编辑的布局。

为什么值得关注：生成式 3D 正从外观与几何表面继续进入拓扑布局，为资产编辑、重建和工业建模提供新的学习型中间表示。

适合谁看：研究 3D 生成、网格重拓扑、数字内容生产和几何 Agent 的团队。

试试看

下载官方检查点，用干净的非敏感三角网格跑一次 4096 点推理，再人工检查拓扑、边流、耗时和后续编辑可用性。

注意点

这是研究原型，不保证网格有效性、可制造性或 CAD 约束；官方 A100 测试中扩散生成约需 65.9 秒，复杂和域外网格可能明显退化。

07NVIDIA Vera CPU美国 / 全球基础设施2026-08-27 发布 / 2026-08-28 观察官方公告

NVIDIA Vera CPU 开始向 Agent 基础设施交付

发生了什么：NVIDIA 更新 Vera CPU 进展，称这款面向 Agent 工作负载的首款自研 CPU 已开始规模交付；AWS 收到首台 Vera CPU 服务器与 Vera Rubin GPU，此前 Anthropic、OpenAI、SpaceXAI 和 OCI 已接收系统。Vera 配备 88 个 Olympus 核心与 1.2TB/s 内存带宽。

为什么值得关注：工具调用、沙箱、编排、长上下文检索和强化学习都把压力移到 CPU，Agent 基础设施不再只是增加 GPU。

适合谁看：规划 Agent 集群、CPU-GPU 协同、云容量和推理成本的基础设施团队。

试试看

先把现有 Agent 负载拆成模型计算、检索、工具、编排与沙箱五类，测出 CPU 饱和和 GPU 空转比例，再判断专用 CPU 的价值。

注意点

最高 1.8 倍单核性能与 2 倍能效来自 NVIDIA 口径，公开资料没有给出完整同代、同功耗、同工作负载的独立对照。

08Google Planetary Prediction Engine全球 / 科学研究2026-08-27 发布 / 2026-08-28 观察一手研究

Google Earth AI 自动完成行星级预测流程

发生了什么：Google Research 发布实验性的 Planetary Prediction Engine。系统从自然语言问题出发，用 LLM 编排地理数据选择、多模态数据整理、模型训练与评估，并以不透明句柄在阶段间传递数据，避免把大型数据集塞进提示词；内部 Feature Gate 会过滤四类目标泄漏。

为什么值得关注：Agent 正从调用现成数据表，走向自动发现证据、构造数据、训练模型并生成可核查报告的完整研究流程。

适合谁看：做地理空间、公共卫生、粮食安全、灾害预测和科学 Agent 的研究团队。

试试看

先复现一个公开小型空间回归任务，逐阶段保留数据来源、特征剔除、训练配置和误差，再和人工管线比较。

注意点

PPE 仍是实验研究能力，结果来自 Google 自身评测；开放网络取数会引入来源质量、时间漂移和许可问题，也不能替代领域专家复核。

本期观察：Agent 产业已经进入“系统工程”阶段。权限、取消、状态、地域、CPU 和研究中间产物，正在共同决定模型能否真正走进生产。
