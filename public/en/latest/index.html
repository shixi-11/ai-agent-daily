The RISC Machine

RISC = the four systems of a production-grade agent or robot

A production-grade agent needs more than a brain. It must keep operating, survive failure, resist overreach, and participate in real organizational workflows.

The industry has delivered an excellent brain, but a production-grade agent also needs a body, an immune system, and a social layer.ALUX is building that complete machine.
R | Resilience / BodyDurable execution, fault tolerance, recovery, and horizontal scale. Without a resilient body, a single failure can wipe out the work.
I | Intelligence / BrainModel loops, memory, tools, and orchestration. This system determines how an agent reasons, invokes tools, and completes complex work.
S | Security / Immune SystemCapability objects, policy approval, rollback, and audit. Without an immune system, recovery and connectivity expand the blast radius of failures.
C | Connectivity / Social LayerCross-company authorization, neutral substrate, session types, and ecosystem connectors. Without a social interface, an agent remains confined to a single product.

AI Agent Radar

Resource placement

Runtimes Reconsider When to Load Resources

AgentCore moves initialization before a snapshot; llama.cpp puts caches and model loading on the local host. Both require weighing first-response latency against recurring resource use.

Work handoffs

Desktop Agents Clarify Reporting Boundaries

OpenCode distinguishes idle subagents from completed background work. Dodaios brings coding-agent results back for desktop review. A visible receipt still needs an actual deliverable.

Editable outputs

Small Tools Preserve Results for Further Work

ZigZag keeps stitches editable, while Yogurt retains local notes and source links. The ability to inspect and revise an output matters after generation ends.

01DeepSeek Application APIsChina2026-11-13 published2026-11-14 observedOfficial primary source

DeepSeek Opens Its Application APIs to Developers

What happened: DeepSeek opened its application API suite on November 13. Existing deepseek-flash endpoints can enable web search, file input, URL reading, and safety checks, with server-side tool calls and context assembly. Search and Fetch, OCR, ASR, and TTS are also standalone APIs. An open-source demo client can import DeepSeek chat history.

Why it matters: This is an application-layer release, not another foundation model. Teams can reuse search and document processing while comparing control, costs, and error handling with a custom toolchain.

Who should care: Product and engineering teams building research assistants, document Q&A, and voice-enabled applications.

Try it

Choose one capability from the Build a Chatbot guide. Use public material to check search citations, file parsing, and URL reading separately, then verify pricing for the calls you actually make.

Keep in mind

This is not V4.2: Flash is still served by V4.1-Flash-1017. Standard and deep-thinking search need different settings. Safety checks do not guarantee compliance or factual accuracy; we have not tested the APIs.

03AWS and NVIDIAUS2026-11-13 published2026-11-14 observedOfficial primary sourceGitHub Stars 1License MIT-0

AWS Sample Evaluates Switchyard Routing by Cost per Solved Task

What happened: AWS published a Bedrock integration example for NVIDIA NeMo Switchyard, deploying LiteLLM and a routing plugin on Fargate. Stage routing uses tool-result history to choose between a more capable model and a lower-cost model; Random routing supports weighted splits. Benchmark runners compare total spending against the number of tasks whose tests pass.

Why it matters: A cheaper call is not necessarily a cheaper completed task. Count failures, retries, and repeated history when comparing routing with a single model.

Who should care: Infrastructure teams comparing routing costs across coding models.

Try it

Read the Stage configuration and benchmark runners. In a non-production account, compare a routed group with both single-model baselines on the same tasks, tracking pass rate and total spend.

Keep in mind

The sample uses switchyard-server 0.3.0 and LiteLLM v1.102.0. AWS labels it experimental and non-production. It is not a new general performance guarantee; we have not deployed it or run the benchmarks.

04llama.cpp 1.0Global2026-11-13 published2026-11-14 observedOfficial primary sourceGitHub Stars 134,874License MIT

llama.cpp 1.0 Cleans Up APIs and Expands Local Inference

What happened: llama.cpp 1.0.0 removes deprecated public APIs and promotes NextN speculative-decoding interfaces into llama.h. It adds FP8 KV caches, a MoE expert cache with a configurable CPU share, and external PLE shard loading. The server gains an OpenAI-compatible speech endpoint alongside fixes for cross-origin access, private-network access, and MCP cancellation.

Why it matters: A 1.0 label does not eliminate migration work. Developers embedding llama.cpp need to check removed interfaces; local applications need to reassess caching, speech support, and server exposure.

Who should care: Engineers embedding llama.cpp, maintaining local model servers, or upgrading desktop inference applications.

Try it

Check the llama.h migration notes, then rerun the same model and prompts in an isolated environment. Measure memory, test the speech endpoint, and verify tool cancellation before replacing a service.

Keep in mind

This is an infrastructure release, not new model weights. Architecture support does not establish weight availability or licensing. The release removes 35 deprecated functions; we have not built it or tested performance.

05ZigZagGlobal2026-11-12 demonstrated2026-11-14 observedCreator’s primary sourceGitHub Stars 608License Apache-2.0

ZigZag Turns AI Artwork Into Editable Stitches

What happened: ZigZag’s creator demonstrated an embroidery editor with MCP support. An agent can create and edit designs alongside a person, converting SVG artwork into stitches for further adjustment. The project exports PES, DST, EXP, JEF, and VP3, or sends designs over Bluetooth to a Brother Skitch PP1. Mac and Windows downloads are available.

Why it matters: An attractive image is not necessarily stitchable. Keeping conversion, stitch checks, and manual editing together connects AI artwork to material and machine constraints.

Who should care: Home embroidery enthusiasts, patch makers, and developers building tools for physical creation.

Try it

Start with the repository and downloads. Check a simple SVG for fills, travel stitches, and hoop fit. Preview the export, then test on scrap fabric before judging stitch quality.

Keep in mind

We reviewed creator documentation and the showcase, not a connected machine. Bluetooth transfer explicitly supports the Skitch PP1. The showcase date is not the first release date, and editable designs do not guarantee suitability for every fabric.

06OpenCode 2.3.0Global2026-11-13 published2026-11-14 observedOfficial primary sourceGitHub Stars 226,671License MIT

OpenCode Runs Subagents in the Background by Default

What happened: OpenCode 2.3.0 makes subagents run in the background by default. They immediately return a session ID and report to the parent when idle, letting the parent continue working. If a subagent becomes idle while its own background work is still running, its report explicitly says the work is unfinished. The terminal also collapses tool activity by default, and the desktop app can search earlier prompts.

Why it matters: Parallel work needs a distinction between reporting and completion, not just concurrent launches. Explicitly reporting unfinished background work helps a parent avoid treating an interim result as a finished deliverable.

Who should care: Developers coordinating parallel research and code changes through open-source agent tools.

Try it

Read the 2.3.0 release notes and start two independent tasks in a small project. Check session IDs, idle reports, and final artifacts before migrating an existing workflow.

Keep in mind

These are published release notes; we have not installed or tested the version. MCP events and timeout-to-background behavior remain experimental flags. Background execution and visible receipts do not guarantee success or recovery.

Brief: Yogurt Keeps Meeting Q&A on Your Computer

What happened: Yogurt records calls, transcribes and summarizes locally, and answers questions across meetings with source links. No bot joins the call. After downloading models, it works offline; a local MCP server can expose read-only notes to an assistant.

Why it matters: Users keep meeting memory locally and choose whether another assistant can read it.

At least 8 GB of memory is required. An MCP assistant may send retrieved content to the cloud; we have not tested it.

02AWS AgentCore V2US2026-11-13 published2026-11-14 observedOfficial primary source

AgentCore Uses Snapshots to Start New Sessions

What happened: AWS detailed AgentCore Runtime V2: it initializes a container when a runtime is created or updated, snapshots the microVM, and restores a separate microVM for each session. Newly supported build hooks cover memory warmup and disk warmup after a test restore. The guide also covers moving initialization, keeping tools running, and prewarming sessions.

Why it matters: The optimization target changes from minimizing repeated initialization to doing reusable work before the snapshot. Imports, local models, and browser files have different restore and first-request costs.

Who should care: Cloud engineers investigating cold starts in agents that use many tools.

Try it

Split platform overhead from total latency with Latency and OverheadLatency. Compare time to first byte and memory charges before and after moving initialization; read the hook example for large files.

Keep in mind

This is an architecture guide, not a two-second guarantee for every application. Network connections may be stale after restore. Both hook calls share 120 seconds, and failed hooks are not retried.
