How the RISC machine works

RISC = the four systems of a production-grade agent or robot body

A production-grade agent needs more than a brain. It must keep operating, survive failures, resist overreach, and participate in real organizational collaboration.

The industry has delivered an excellent brain, but production-grade agents still need a body, an immune system, and a social layer.ALUX is building the complete machine.
R｜Resilience / BodyDurable execution, fault tolerance, recovery, and horizontal scale. Without a resilient body, one failure can erase the work.
I｜Intelligence / BrainModel loops, memory, tools, and orchestration. It determines how an agent reasons, acts, and completes complex work.
S｜Security / ImmuneCapability objects, policy approval, rollback, and audit. Without an immune system, permissions and recovery expand the blast radius.
C｜Connectivity / SocialCross-company authorization, neutral ground, session types, and ecosystem connectors. Without a social layer, agents remain trapped inside individual products.

01Microsoft Agent FrameworkUnited States / Global open sourceReleased 2026-07-30 / Observed 2026-07-31Official release

Microsoft Agent Framework 1.13 Brings Human Responses into Replayable Checkpoints

What happened: Python 1.13.0 adds reusable session stores and full Foundry Responses session persistence. In a breaking change, workflow checkpoints can now replay from the original input and human-in-the-loop responses. The same release fixes approval continuation, subworkflow restoration, and durable checkpoint storage.

Why it matters to ALUX: This is today’s closest external match to ALUX’s core value. Recovery is no longer just loading a snapshot; the system must show how initial input, human intervention, approvals, and subworkflows produced the current state. ALUX can extend that chain into a verifiable long-running transaction that also carries capability constraints and effect cursors.

Recommended action and artifact: Define a Human-in-the-Loop Replay Envelope v0 binding initial_input, human_response, approval_decision, checkpoint_ref, effect_cursor, and replay_verdict. Artifact: Human-in-the-Loop Replay Envelope v0.

RISC: R primary · Resilience / BodyS secondary · Security / Immune

This signal primarily affects the robot’s Resilience / Body system: checkpoints, sessions, and subworkflows must recover and replay. Security / Immune is secondary because human approval decisions must remain consistent after continuation.

Durable executionYesThe release adds reusable session stores, full Responses session persistence, and durable checkpoint storage.
Failover recoveryYesWorkflows can replay from initial input and human responses, with fixes for subworkflow restoration and approval continuation.
Partnership / learning window

Use Microsoft Agent Framework as a priority runtime-adapter reference for checkpoint import, approval events, and external-effect receipts. Study how it places session storage, human responses, approval continuation, and subworkflow recovery in one release contract.

Evidence boundary

The release demonstrates framework-level replay and recovery improvements. It does not establish unforgeable capabilities, idempotent external effects, bit-exact verification, or neutral cross-company execution.

What changed today

Microsoft now unifies original input, human responses, approvals, and subworkflow restoration in a replayable checkpoint contract instead of patching isolated persistence components.

02CrewAIUnited States / Global open sourceReleased 2026-07-30 / Observed 2026-07-31Official release

CrewAI 1.15.9 Stops Reporting Tool Failures as Successes

What happened: Version 1.15.9 surfaces tool failures instead of presenting them as successful outcomes and emits a FlowFailedEvent when a flow fails. It also adds progressive disclosure for skills.

Why it matters to ALUX: Tool-call results must match real-world effects; that is the minimum requirement for a trustworthy terminal verdict in a long-running transaction. ALUX’s differentiation is not another failure event, but a replayable responsibility chain that binds tool results, external effects, compensation, and the final verdict.

Recommended action and artifact: Define a Tool Outcome Receipt v0 distinguishing requested, invoked, effect_observed, failed, compensated, and terminal_verdict. Artifact: Tool Outcome Receipt v0.

RISC: R primary · Resilience / BodyS secondary · Security / Immune

This signal primarily affects the robot’s Resilience / Body system because the runtime must recognize real failure and issue a truthful terminal state. Security / Immune is secondary because false success breaks auditability and accountability.

Fault toleranceYesTool failures are surfaced explicitly and failed flows emit FlowFailedEvent.
Failover recoveryPartialFailure is detected accurately, but the release does not define recovery, retry, or compensation semantics.
Partnership / learning window

Use CrewAI as an execution adapter to map tool failures and flow termination into ALUX effect receipts. Study its explicit failure events and its progressive-disclosure approach to skill catalogs.

Evidence boundary

FlowFailedEvent remains a framework event. The release does not prove tamper resistance, whether a tool created partial external effects, or whether failure can be rolled back atomically.

What changed today

CrewAI now converts the semantic error of treating tool failure as success into a formal failure signal and gives flow failure its own event.

04Google ADKUnited States / Global open sourceReleased 2026-07-30 / Observed 2026-07-31Official release

Google ADK 2.6 Adds Per-Invocation Authentication Headers for A2A Agent-Card Fetches

RISC: S primary · Security / ImmuneC secondary · Connectivity / Social

This signal primarily affects the robot’s Security / Immune system because every A2A invocation needs its own authentication boundary. Connectivity / Social is secondary because that credential is used to discover and enter another agent’s collaboration surface.

Capability objectPartialAuthentication headers can be supplied per invocation, but the release does not establish unforgeable or attenuated capability objects.
Policy approvalPartialCredential scope is narrowed to the invocation, but no approval or revocation flow is documented.
Partnership / learning window

Build an ADK A2A capability bridge that maps each agent-card fetch and subsequent session establishment to an ALUX capability grant. Study its API design for placing authentication context on each invocation.

Evidence boundary

The authentication header may still be a copyable bearer secret. The release does not establish least privilege, attenuation, revocation, neutral cross-company ground, or full session audit.

What changed today

A2A agent-card retrieval moves from static connection configuration to per-invocation authentication context.

06LangGraphUnited States / Global open sourceReleased 2026-07-30 / Observed 2026-07-31Official release

LangGraph 3.1.1 Fixes Cross-Segment Checkpoint Namespace Matches

What happened: Checkpoint packages 3.1.1 for PostgreSQL and SQLite constrain namespace matching to segment boundaries, preventing similar prefixes from causing one state domain to match another.

Why it matters to ALUX: Persistent-state isolation often fails in naming and matching details rather than in high-level security claims. ALUX should treat state namespaces as capability paths and require verifiable scope evidence for every read, restore, and derivation.

Recommended action and artifact: Define a Capability Namespace Mapping v0 with namespace_segment, owner, grant, checkpoint_ref, and restore_scope. Artifact: Capability Namespace Mapping v0.

RISC: S primary · Security / ImmuneR secondary · Resilience / Body

This signal primarily affects the robot’s Security / Immune system because checkpoint namespaces must prevent state leakage. Resilience / Body is secondary because incorrect scope can restore the wrong state.

Isolation boundaryYesCheckpoint namespace matching is constrained to path-segment boundaries, directly fixing state-scope leakage.
Capability objectNoThe release proves a namespace-matching fix, not an unforgeable capability object.
Partnership / learning window

Design an ALUX namespace adapter for LangGraph checkpoint stores that aligns threads and checkpoints with capability paths. Study the engineering discipline of fixing state-scope contamination at segment boundaries.

Evidence boundary

Segment-aware string matching fixes one class of false match. It is not tenant isolation, object-capability security, or execution sandboxing, and database authorization errors can still cross boundaries.

What changed today

LangGraph identifies checkpoint isolation as a namespace-segment boundary problem and fixes it across both PostgreSQL and SQLite stores.

Funding and partnership window

Most direct partnership surface: Microsoft Agent Framework is the recovery and human-approval reference. CrewAI, Deep Agents, Google ADK, Kimi Code, and LangGraph are framework-adapter targets. Phoenix is the observability outlet, while LiteLLM is the multi-model gateway and artifact-verification entry point.
Capital narrative: No newly verified funding amount warrants inclusion today. The stronger structural signal is that leading frameworks are separately adding accountability fields for recovery, failure, trust, authentication, plugin provenance, state isolation, and artifact supply chains. ALUX can consolidate those fields into a verifiable production-grade runtime protocol.

Technical and product implications

Priority product: Agent Recovery Responsibility Envelope v0. Suggested fields: execution_id, initial_input_hash, human_response_ref, capability_set, artifact_digest, checkpoint_ref, effect_cursor, terminal_verdict, and replay_ref.
Priority demo: Interrupt a Microsoft Agent Framework workflow after human approval, then restore it while validating the LiteLLM image signature, LangGraph state namespace, and Google ADK invocation capability. Delegate a subagent through a Kimi plugin, require CrewAI tool failure to produce a truthful terminal state, use Phoenix only to display traces, and let the ALUX receipt prove state and effects.

Evidence boundaries

ALUX must not be described as a fully delivered agent platform. The underlying TVM already provides key foundations including native concurrency, durable execution, capability security, run recording, and bit-exact replay audit. The agent product layer, observability, dashboards, tracing, and evaluation tooling still need to be built and funded. TVM does not make the LLM itself deterministic; it records model outputs and environmental inputs so orchestration, permissions, state transitions, and audits can be replayed and verified. Framework checkpoints, failure events, workspace trust, A2A authentication headers, plugin manifests, namespace fixes, trace counts, and image signatures do not independently prove idempotent external effects, cross-step atomic rollback, unforgeable capabilities, or neutral cross-company collaboration.
