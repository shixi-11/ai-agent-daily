RISC machine primer

RISC = the four systems of a production-grade agent machine

A production-grade agent needs more than a brain. It must keep operating, survive failure, resist overreach, and participate in real organizational workflows.

The industry has delivered an excellent brain, but a production-grade agent also needs a body, an immune system, and a social layer. ALUX is building that complete machine.
R | Resilience / Body Durable execution, fault tolerance, recovery, and horizontal scale. Without a resilient body, a single failure can wipe out the work.
I | Intelligence / Brain Model loops, memory, tools, and orchestration. This system determines how an agent reasons, invokes tools, and completes complex work.
S | Security / Immune Capability objects, policy approval, rollback, and audit. Without an immune system, recovery and connectivity expand the blast radius of failures.
C | Connectivity / Social Cross-company delegation, neutral ground, session types, and ecosystem connectors. Without a social interface, an agent remains confined to a single product.

ALUX daily radar

01 OpenAI Codex United States / Global open source Released 2026-08-20 / observed 2026-08-21 Official release

Codex 0.149 unifies session queues, permission recovery, and transport reconnects

What changed: Version 0.149.0 adds a codex agents dashboard for finding, starting, opening, renaming, and stopping tasks, plus codex queue for messaging local or remote sessions. It also fixes queue wakeups for idle sessions, restores the original permission profile on resumed or forked threads, reconnects WebRTC after transport loss, and bounds replay buffers for inactive threads.

Why it matters to ALUX: Sessions are becoming addressable run objects that can be woken, recovered, and tied to a permission version. ALUX should carry those states in one identity-and-recovery receipt for a long-running transaction.

Recommended action and artifact: Define a Session Lifecycle Receipt v0 binding run_id, parent_run, queue_cursor, permission_profile_hash, transport_epoch, replay_window, and terminal_state. Artifact: Session Lifecycle Receipt v0.

RISC: R primary · Resilience / Body S secondary · Security / Immune

This signal primarily affects Resilience / Body: queue wakeups, thread recovery, transport reconnects, and replay limits determine whether a session remains operational. Permission restoration also touches Security / Immune.

Durable execution Partial Tasks can be addressed through a dashboard, messaged remotely, and continued from resumed or forked threads.
Fault tolerance Yes Queued messages reliably wake idle sessions, and WebRTC reconnects without losing pending output.
Partnership / learning window

Use Codex as a coding-agent integration surface for mapping forks, recovery, and remote sessions into ALUX durable execution and capability versions. Study session directories, message queues, permission snapshots, transport reconnects, and replay limits as one lifecycle.

Evidence boundary

The release demonstrates product-level recovery and control-plane fixes, not cross-node consensus, external-effect deduplication, atomic rollback, or bit-exact audit.

What is new today

The stable 0.149.0 release brings the codex agents dashboard, cross-session queue, permission restoration, WebRTC reconnects, and bounded replay buffers into one lifecycle update.

02 Anthropic Claude Code United States / Global developers Released 2026-08-20 / observed 2026-08-21 Official release

Claude Code 2.1.238 turns self-hosted shutdown and session handoff into a recovery contract

What changed: Version 2.1.238 gives self-hosted runners a deferred-shutdown window: after SIGTERM they keep serving attached sessions, then park what remains before exiting. It also prevents a single slow or missed poll from handing a healthy session to another runner and releases subagent tool results once they leave the recent display window.

Why it matters to ALUX: Graceful shutdown, session parking, mistaken handoff, and memory limits now sit inside the runtime boundary. ALUX can model park, handoff, and resume as verifiable state transitions.

Recommended action and artifact: Define a Runner Park / Handoff Receipt v0 covering runner_lease, shutdown_deadline, session_set, park_cursor, handoff_target, and unresolved_effects. Artifact: Runner Park / Handoff Receipt v0.

RISC: R primary · Resilience / Body S secondary · Security / Immune

This signal primarily affects Resilience / Body: shutdown, parking, handoff, and resource reclamation determine whether self-hosted sessions recover cleanly. Fresh proxy authorization also touches Security / Immune.

Durable execution Partial Attached sessions keep running after SIGTERM and are parked when the shutdown deadline expires.
Fault tolerance Yes A single slow or missed poll no longer causes the server to reassign a healthy session.
Partnership / learning window

Use Claude Code self-hosted runners as a recovery-semantics benchmark for an ALUX runner lease and park receipt. Study shutdown grace periods, health leases, session parking, and long-session resource reclamation together.

Evidence boundary

Parking is not necessarily a durable checkpoint, and preventing mistaken handoff does not prove replicated state. The release does not explain external-effect deduplication.

What is new today

Version 2.1.238 establishes explicit deferred shutdown, parking, and healthy-session handoff semantics for self-hosted runners.

03 E2B United States / Global open source Released 2026-08-20 / observed 2026-08-21 Official release

E2B 2.43 places secrets and workload tokens behind a write-only control plane

What changed: Version 2.43.0 adds SDK secrets management: values can be created or updated but read APIs return metadata only, while the runtime resolves current values through placeholders. Network transforms now reject unregistered IAM token names at use time instead of forwarding undefined values or built-in function text as credentials.

Why it matters to ALUX: Unreadable values, validated references, and fail-closed use move credentials closer to controlled capabilities. ALUX can add unforgeability, attenuation, and revocation at the protocol layer.

Recommended action and artifact: Define a Secret Capability Reference v0 containing secret_ref, issuer, audience, scope, rotation_epoch, readability, revocation, and effect_binding. Artifact: Secret Capability Reference v0.

RISC: S primary · Security / Immune C secondary · Connectivity / Social

This signal primarily affects Security / Immune: secret values are unreadable and unknown token references fail closed. Runtime resolution into external services also touches Connectivity / Social.

Capability object Partial Secrets are used through references and placeholders; values are never returned through the read surface.
Isolation boundary Yes The management plane returns metadata only; secret values remain write-only.
Partnership / learning window

Evaluate E2B as an ALUX tool-execution sandbox integrated with secret references, egress identity, and run receipts. Study write-only secrets, metadata access, runtime placeholder resolution, and fail-closed token references.

Evidence boundary

E2B still controls these platform objects; they are not protocol-level OCAPs. Rotation, deletion, and metadata do not establish third-party-verifiable or cross-company authorization.

What is new today

Version 2.43.0 puts write-only secret lifecycle and network-token reference validation into the same SDK control plane.

Qwen Code 0.21.15 resumes interrupted reviews only when the code head is unchanged

Recommended action and artifact: Define a Review Resume Invariant v0 binding repo_head, workspace_hash, history_cursor, tool_call_ids, attachment_set, and permission_profile_hash. Artifact: Review Resume Invariant v0.

RISC: R primary · Resilience / Body S secondary · Security / Immune

This signal primarily affects Resilience / Body: interrupted review resumes only when the input baseline remains valid. Attachment handling and approval presentation also touch Security / Immune.

Durable execution Yes Reviews and CI retries can resume, and Web Shell attachments persist.
Failover recovery Yes Resume is gated on the pull-request head remaining unchanged.

05 Moonshot AI Kimi Code China / Global open source Released 2026-08-20 / observed 2026-08-21 Official release

Kimi Code 0.38 uses WaitFor to bring background work back into the current turn

What changed: Version 0.38.0 adds WaitFor, allowing an agent to wait for a background task inside the current turn instead of ending the turn and being invoked again. Foreground and background subagents are labeled in the message stream, malformed or externally edited configuration no longer loses entries, and existing files must be read before they are edited.

Why it matters to ALUX: Waiting is moving from a UI convention into a tool contract. ALUX can encode the wait condition, deadline, return path, and turn ownership as session types within a long-running transaction.

Recommended action and artifact: Define an Awaitable Delegation Contract v0 covering parent_run, child_run, wait_condition, deadline, return_channel, cancel_policy, and effect_owner. Artifact: Awaitable Delegation Contract v0.

RISC: R primary · Resilience / Body C secondary · Connectivity / Social

This signal primarily affects Resilience / Body: the parent turn can wait for background work while preserving execution continuity. Foreground/background roles and return paths also touch Connectivity / Social.

Durable execution Partial WaitFor keeps the parent turn open until background work completes.
Fault tolerance Partial Malformed or externally edited configuration no longer loses existing entries.
Partnership / learning window

Use Kimi Code as a China-market multi-agent entry point for compiling WaitFor semantics into TVM joins, waiting operations, and session-type constraints. Study in-turn waiting, background-task ownership, configuration preservation, and read-before-write execution constraints.

Evidence boundary

WaitFor proves in-turn waiting, not crash recovery, cross-node resume, or atomic external effects. Read-before-write is not a complete object-capability model.

What is new today

Version 0.38.0 lets a parent agent wait explicitly for background work inside the same turn and exposes foreground/background mode to operators.

07 Cloudflare Agents United States / Global open source Released 2026-08-18 / observed 2026-08-21 Official release

Cloudflare Hono Agents prevents rejected connections from falling through middleware

What changed: hono-agents 3.0.12 fixes a path where an HTTP rejection returned by onBeforeConnect was ignored and the request continued into downstream Hono handlers. Rejection responses now terminate the path; applications that relied on fallthrough must narrow the agentsMiddleware mount or configure a dedicated agent route prefix.

Why it matters to ALUX: A rejected connection must terminate its execution path rather than being reinterpreted by later routing. ALUX policy gates likewise need to be non-bypassable, fail closed, and bind to a specific session entry point.

Recommended action and artifact: Define a Connection Admission Verdict v0 containing route_scope, principal_ref, policy_hash, verdict, terminal_response, and session_effect. Artifact: Connection Admission Verdict v0.

RISC: S primary · Security / Immune C secondary · Connectivity / Social

This signal primarily affects Security / Immune: a rejected connection must stop rather than fall through to another execution path. Routing and WebSocket session establishment also touch Connectivity / Social.

Policy approval Yes The rejection returned by onBeforeConnect is now terminal.
Isolation boundary Yes Applications must narrow middleware scope or use a dedicated agent route prefix.
Partnership / learning window

Use Cloudflare Agents as an edge-session entry point for mapping connection rejection into ALUX capability decisions and session termination. Study the relationship between pre-connect hooks, terminal rejection, and route scope.

Evidence boundary

This framework patch does not prove that every downstream middleware path is non-bypassable, nor does it provide replay audit, rollback, or cross-company authorization.

What is new today

Version 3.0.12 makes connection rejection terminal and explicitly requires a narrower agent routing scope.

Funding / partnership window

Most direct integration surfaces: E2B for secret and sandbox capabilities; Codex, Claude Code, Qwen Code, Kimi, and Agno for session and background-run adapters; Cloudflare Agents and Stagehand for edge admission and browser-effect verification.
Capital narrative: No sufficiently reliable new funding amount enters today’s issue. The more valuable structural shift is that leading agent products are adding state, authority, and terminal semantics to recovery. ALUX can unify those patches as a verifiable long-running transaction contract.

Technical / product implication

Priority product: Session Lifecycle Receipt v0. Proposed fields: run_id, parent_run, owner, queue_cursor, permission_profile_hash, input_snapshot_hash, wait_condition, runner_lease, transport_epoch, terminal_state, effect_refs, and replay_ref.
Priority demo: Have a parent agent delegate a background browser task, then trigger a queue wakeup, a connection rejection, runner shutdown, and recovery. Verify that inputs remain unchanged, authority never escalates, secrets stay unreadable, rejection does not fall through, and the browser effect commits once.

Evidence boundaries

ALUX must not be described as a complete agent platform already in production. The underlying TVM provides key foundations—including native concurrency, durable execution, capability security, run recording, and bit-exact replay audit—while the agent product layer, observability, dashboards, tracing, and evaluation tooling remain to be built and funded. TVM does not make the LLM deterministic; it records model outputs and environmental inputs so orchestration, permissions, state transitions, and audit can be replayed and verified. Session recovery, parking, WaitFor, write-only secrets, OAuth, coordinate normalization, and connection rejection do not independently prove cross-node recovery, unforgeable capabilities, atomic rollback, external-effect deduplication, or neutral cross-company collaboration. Agno 3.0 remains an alpha prerelease.
