RISC机器说明

RISC = 生产级 Agent / 机器人身体的四个系统

一个真正能上生产的 Agent，不能只有大脑。它还要持续行动、扛住故障、抵御越权，并进入真实组织协作。

行业已经交付了一颗出色的大脑，但生产级 Agent 还需要机体、免疫和社会。ALUX 构建的，就是这台完整机器。
R｜强韧 / 机体持久执行、容错、恢复与水平扩展。身体站不住，一次故障就会把工作清空。
I｜智能 / 大脑模型循环、记忆、工具与编排。它决定 Agent 如何思考、调用和完成复杂工作。
S｜安全 / 免疫能力对象、策略审批、回滚与审计。没有免疫，恢复与连接会扩大失控半径。
C｜连接 / 社会跨公司授权、中立基底、会话类型与生态连接。没有社会接口，Agent 只能停在单一产品里。

01DeepSeek应用API中国2026-11-13 发布2026-11-14 观察官方一手来源

DeepSeek把应用能力开放给开发者

发生了什么：DeepSeek在11月13日开放整套应用API：已有deepseek-flash可通过参数启用联网搜索、文件输入、链接读取与安全检查，服务端处理工具调用和上下文拼接。Search与Fetch、OCR、ASR和TTS也可单独调用，官方另提供能导入聊天历史的开源演示客户端。

为什么值得关注：这次变化在应用层，而非又一个基础模型。团队可直接复用搜索和文档处理能力，但要比较服务端代办与自建工具链各自的可控性、费用及错误处理。

适合谁看：开发研究助手、文档问答和带语音交互应用的产品与工程团队。

试试看

从官方Build a Chatbot指南选一种工具，用同一份公开材料分别检查搜索引用、文件解析与链接读取；再按实际调用路径核对计费。

注意点

并非V4.2首发，当前Flash仍由V4.1-Flash-1017提供。普通搜索与深度思考搜索配置不同；安全检查不是业务合规或事实正确性的完整保证，本期未实测。

GitHub开源发现

Stars为成稿时的关注度快照，不代表质量排名。

03AWS与NVIDIA美国2026-11-13 发布2026-11-14 观察官方一手来源GitHub Stars 1许可证 MIT-0

Switchyard示例按解题成本比较模型路由

发生了什么：AWS发布Bedrock与NVIDIA NeMo Switchyard集成示例，把LiteLLM网关和路由插件部署到Fargate。Stage策略依据历史工具结果，在能力较强与成本较低的两个模型间选择；Random策略用于加权分流。配套基准以测试通过的任务数计算平均解题成本。

为什么值得关注：便宜的单次调用不一定带来便宜的完成结果。把失败尝试、重试和多轮历史一并计费，再与单模型基线比较，才能判断路由有没有真正节省成本。

适合谁看：已有编程Agent、准备比较多模型路由与整项任务费用的基础设施工程团队。

试试看

阅读示例的Stage配置与基准运行器，在非生产账户用同一任务集比较两个单模型基线和路由组，同时记录通过率与总支出。

注意点

示例使用switchyard-server 0.3.0与LiteLLM v1.102.0，官方明确为实验集成、非生产示例。文中不是新增通用性能保证；本期未部署或运行基准。

04llama.cpp 1.0全球2026-11-13 发布2026-11-14 观察官方一手来源GitHub Stars 134,874许可证 MIT

llama.cpp 1.0整理API并扩展本地推理

发生了什么：llama.cpp发布1.0.0，移除已弃用公共API，将NextN推测解码接口纳入llama.h，并增加FP8 KV缓存、可配置CPU占比的MoE专家缓存及外部PLE分片加载。服务端新增兼容OpenAI的语音合成端点，同时修补跨源、私网访问与MCP工具取消相关问题。

为什么值得关注：版本号到1.0不代表兼容性可以忽略。对嵌入式调用者，更直接的工作是检查删除的接口；对本地应用，则要重新评估缓存、语音与服务端暴露范围。

适合谁看：嵌入llama.cpp、维护本地模型服务或升级桌面推理应用的工程师。

试试看

先对照发行说明检查llama.h迁移点，再在隔离环境用原模型和原提示复跑；分别测内存占用、语音端点与工具取消，不直接覆盖现有服务。

注意点

这是基础设施版本，不是新模型权重。支持某架构不代表全部权重或许可可用；35个弃用函数被移除，本期未编译或验证性能。

05ZigZag全球2026-11-12 公开展示2026-11-14 观察作者一手来源GitHub Stars 608许可证 Apache-2.0

ZigZag让AI图案变成可编辑针脚

发生了什么：ZigZag作者展示带MCP接口的刺绣编辑器：AI可与人共同创建和修改图案，把SVG变成针脚，再由用户调整。项目可导出PES、DST、EXP、JEF与VP3格式，也能通过蓝牙将设计发给Brother Skitch PP1。Mac和Windows已有下载入口。

为什么值得关注：生成一张好看的图，不等于刺绣机能把它缝出来。把图形转换、针脚检查与人工调整保留在同一工具里，让AI创作接上材料与机器限制。

适合谁看：有家用刺绣机、制作布贴与手工作品的创作者，以及研究实体制作工具的开发者。

试试看

从官方仓库和下载页开始，用简单自有SVG检查填充、跳线和绣框范围；先导出文件预览，再用废布试缝，不把画面效果直接当成针脚质量。

注意点

本期核验作者文档与展示，未连接机器。蓝牙直传只明确支持Skitch PP1；展示日期不是首次发行日，图案可编辑也不保证适合所有布料。

06OpenCode 2.3.0全球2026-11-13 发布2026-11-14 观察官方一手来源GitHub Stars 226,671许可证 MIT

OpenCode让子Agent默认后台运行

发生了什么：OpenCode 2.3.0把子Agent改为默认后台运行，立即返回会话ID，进入空闲时向父会话汇报；父会话可同时继续工作。若子Agent仍有后台任务，汇报会明确未完成。此外，终端默认折叠工具活动，桌面端可搜索并跳转到较早的提示。

为什么值得关注：并行工作的关键不只是同时启动，还要区分已汇报与已完成。把仍在运行的后台任务写进返回状态，能减少父Agent把阶段结果误当最终交付。

适合谁看：使用开源编程Agent、需要编排并行研究与代码修改的开发者和工具作者。

试试看

阅读2.3.0发行说明，在小型项目启动两个独立子任务，检查返回会话ID、空闲回执与最终产物是否一致，再决定是否迁移现有工作流。

注意点

这是已发布版本说明，本期未安装实测。MCP events与超时转后台仍需实验开关；后台执行和可见回执不代表任务必定成功或能自动恢复。

02AWS AgentCore V2美国2026-11-13 发布2026-11-14 观察官方一手来源

AgentCore用快照缩短新会话启动

发生了什么：AWS公开AgentCore Runtime V2启动架构：创建或更新运行时时先初始化容器，再保存微虚机快照，新会话各自恢复到独立微虚机。新支持的构建钩子分内存预热与测试恢复后的磁盘预热；文章同时给出初始化前移、常驻工具与提前开启会话等实践。

为什么值得关注：优化方向从缩小每次启动的初始化，变为把可复用工作移到快照之前。工具导入、模型加载与浏览器文件各有不同代价，需要分别检查恢复时间和首个请求。

适合谁看：运行交互式或多工具Agent、需要定位冷启动延迟的云平台与应用工程团队。

试试看

先用Latency与OverheadLatency拆出平台耗时，再比较初始化前移前后的首字节延迟及内存费用；需要加载大文件时阅读构建钩子示例。

注意点

这是官方架构与实践说明，不是所有应用都能两秒启动的保证。快照前的网络连接恢复后可能失效；两个钩子调用共用120秒，失败不会自动重试。
