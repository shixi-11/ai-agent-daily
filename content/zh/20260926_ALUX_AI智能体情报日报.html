RISC机器说明

RISC = 生产级 Agent / 机器人身体的四个系统

一个真正能上生产的 Agent，不能只有大脑。它还要持续行动、扛住故障、抵御越权，并进入真实组织协作。

行业已经交付了一颗出色的大脑，但生产级 Agent 还需要机体、免疫和社会。ALUX 构建的，就是这台完整机器。
R｜强韧 / 机体持久执行、容错、恢复与水平扩展。身体站不住，一次故障就会把工作清空。
I｜智能 / 大脑模型循环、记忆、工具与编排。它决定 Agent 如何思考、调用和完成复杂工作。
S｜安全 / 免疫能力对象、策略审批、回滚与审计。没有免疫，恢复与连接会扩大失控半径。
C｜连接 / 社会跨公司授权、中立基底、会话类型与生态连接。没有社会接口，Agent 只能停在单一产品里。

AI Agent雷达

持续执行

常驻助手需要可检查的权限

Copilot让助手持续工作，Compass把文档权限放进检索。执行时间拉长后，系统必须能说明访问了什么，以及凭什么访问。

互动创作

生成作品开始接受后续操作

PixVerse把动作带入生成世界，Horizon把生成接到编辑器。作品是否允许继续探索和修改，正在成为比首轮惊艳更持久的价值。

独立核验

决策记录让能力更容易拆解

Jev展示模型选择与外围规划如何配合，奖励投机研究则说明审查代码仍会漏检。可见过程有助理解，但结果仍需独立核验。

01Microsoft Copilot美国发布于2026-09-25 / 观察于2026-09-26一手资料

Copilot给常驻助手配上独立工作空间

发生了什么：微软公布新版Copilot：Home连接聊天与协作，Code可在受管环境构建内部应用，Autopilot拥有独立身份、记忆和云端工作空间，能经由Teams与Outlook持续处理事务。各功能按不同预览计划分批开放，并非全体用户立即可用。

为什么值得关注：助手的价值从回答一次问题，转向离开聊天窗口后还能继续工作。身份、权限和费用因此成为产品能力的一部分，而非上线后的补丁。

适合谁看：需要跨办公应用推进事务的团队，以及负责租户权限和成本管理的管理员。

试试看

查看官方功能与预览安排，先选一项可核对结果的内部事务，明确允许访问的资料和单次运行预算。

注意点

Autopilot仍是私人预览；Cowork、Code及Autopilot采用用量计费，不能按现有订阅推定全部包含。

03Cohere Compass Cloud加拿大发布于2026-09-25 / 观察于2026-09-26一手资料

Compass Cloud把检索流程收进同一服务

发生了什么：Cohere推出Compass Cloud私人测试，将连接数据、解析、嵌入、索引、检索与重排序组合为托管服务，并提供API和独立MCP服务器。检索会检查文档访问权限；源文档与嵌入分离，使更换嵌入模型不必重新抓取全部原始资料。

为什么值得关注：企业检索的难点往往不在接上一个模型，而在更新数据、维持权限与更换组件。把这些环节一起管理，有望减少系统接缝。

适合谁看：构建企业知识助手、维护内部搜索，以及负责文档访问治理的技术团队。

试试看

通过官方页面申请测试，选一组具有不同访问权限的文档，验证检索结果及更换嵌入模型后的更新流程。

注意点

目前需要申请私人测试，不能当作全面开放服务；官方内部检索基准也不能直接推定为企业实际业务收益。

07Microsoft OmniParser美国发布于2026-09-23 / 观察于2026-09-26一手资料

OmniParser新增MIT许可检测器

发生了什么：微软在OmniParser模型仓库新增icon_detect_v3权重，以YOLOv9-E识别屏幕中的可交互区域，并采用MIT许可。官方提供自包含的TorchScript推理方式，可与原有图标描述模型组合；旧版检测器仍保留，许可没有随之改变。

为什么值得关注：屏幕操作助手需要把截图转成可执行目标。新权重提供了另一条许可与部署路径，团队可以重新评估组件组合，而不必误把整个旧模型包视为MIT许可。

适合谁看：开发桌面操作助手、评估视觉定位组件，以及需要核对分发许可的团队。

试试看

阅读新增检测器说明，用自己的截图测试小图标召回，并核对缩放留边后的坐标还原是否与原图一致。

注意点

MIT适用于新增检测器，旧YOLOv8检测器仍为AGPL-3.0；置信度阈值要按界面校准，不能据此推定准确率全面提升。

08Ollaya 0.6全球发布于2026-09-25 / 观察于2026-09-26GitHub Stars 159许可证 Apache-2.0一手资料

Ollaya把小型决策模型搬到本机

发生了什么：Ollaya于9月25日发布0.6.0，扩展本地决策模型支持，并提供命令审查预设。同日的桌面与MCP等更新补齐使用入口：模型通过一次前向计算输出选项、分数或是非判断，而不是先生成一段解释文字；运行基于ONNX。

为什么值得关注：并非每次分流和审批都需要大模型写长答案。把有限选项判断放在本地，有机会缩短调用路径，但效果仍取决于任务和训练适配。

适合谁看：需要本地分类、工具路由或命令初筛的开发者，以及关注推理成本的团队。

试试看

从仓库按系统安装，拿一组有人工标签的真实判断题比较模型结果；先用于辅助分流，再考虑扩大自动执行范围。

注意点

运行时为Apache-2.0，各模型许可需分别核对；苹果芯片当前走CPU而非Metal，输出概率也不是正确性保证。

10LFM2.5-VL-DSpark美国发布于2026-09-24 / 观察于2026-09-26一手资料

Liquid AI用小草稿模型加速视觉回答

发生了什么：Liquid AI发布面向LFM2.5-VL-3B的实验性VL-DSpark草稿模型，约含2.8亿参数。它先提出候选词元，再由目标模型验证；官方M5 Max测试报告端到端最高2.62倍加速，并保持与贪心解码结果一致，相关权重已提供下载。

为什么值得关注：加速不一定来自换一个更大的视觉模型。草稿与验证分工能减少解码等待，但总体收益还受图像编码、输入长度和实际运行后端影响。

适合谁看：部署本地视觉助手、优化交互延迟，以及维护多模态推理后端的团队。

试试看

按官方示例下载匹配权重，检查所用后端的补丁或版本，再用真实图片与问题测量端到端延迟和输出一致性。

注意点

该方案仍属实验性，部分后端需对应补丁；最高倍数来自特定硬件测试，不能当作所有设备或图像预处理的加速承诺。
