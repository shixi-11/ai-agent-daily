RISC機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它還要持續行動、扛住故障、抵禦越權，並進入真實組織協作。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體持久執行、容錯、恢復與水平擴充套件。身體站不住，一次故障就會把工作清空。
I｜智慧 / 大腦模型迴圈、記憶、工具與編排。它決定 Agent 如何思考、呼叫和完成複雜工作。
S｜安全 / 免疫能力物件、策略審批、回滾與審計。沒有免疫，恢復與連線會擴大失控半徑。
C｜連線 / 社會跨公司授權、中立基底、會話型別與生態連線。沒有社會介面，Agent 只能停在單一產品裡。

01OpenAI Codex美國 / 全球開發者2026-08-20 釋出 / 2026-08-21 觀察官方釋出

Codex 0.149 把多會話任務變成可排隊的工作流

發生了什麼：Codex 0.149 新增 agents 面板和 codex queue，可搜尋、啟動、開啟、重新命名與停止任務，並向本地或遠端會話投遞訊息；同時修復空閒喚醒、許可權恢復和 WebRTC 重連。

為什麼值得關注：AI 程式設計工具開始從單視窗對話轉向可定址、可排隊、可恢復的多工工作臺。

適合誰看：同時維護多個倉庫、遠端任務或長時間 coding agent 流程的團隊。

試試看

讓兩個會話分別處理不同問題，再用 queue 投遞後續指令，檢查恢復後的許可權和上下文。

注意點

這是會話管理與重連改進，不等於跨節點一致性或外部操作的原子回滾。

02Anthropic Claude Code美國 / 全球開發者2026-08-20 釋出 / 2026-08-21 觀察官方釋出

Claude Code 2.1.238 讓自託管任務在停機前先安穩停放

發生了什麼：自託管 runner 收到 SIGTERM 後會在寬限期內繼續服務已連線會話，到期再 park 並退出；新版也修復慢輪詢或丟包導致健康會話被誤交接的問題。

為什麼值得關注：長任務不僅怕崩潰，也怕被誤判崩潰；寬限期和停放機制讓交接邊界更清楚。

適合誰看：自託管 Claude Code、頻繁維護 runner，或需要保留長任務的團隊。

試試看

在測試環境傳送 SIGTERM，分別觀察連線中、空閒和剛斷線會話最終停放到哪裡。

注意點

park 不自動等於完整持久 checkpoint，也未證明外部操作具備去重語義。

03E2B美國 / 全球開發者2026-08-20 釋出 / 2026-08-21 觀察官方釋出

E2B 2.43 讓沙箱裡的秘密可以使用但不能讀回

發生了什麼：E2B Secrets Management 允許建立或更新秘密值，但讀取介面只返回後設資料；執行時透過佔位符解析當前值，未註冊 IAM token 會在使用時直接報錯。

為什麼值得關注：Agent 可以拿憑據做事，卻不能把原值讀出、寫進日誌或帶回對話。

適合誰看：把 GitHub、資料庫、雲端 API 或內部系統交給 Agent 呼叫的團隊。

試試看

把低風險測試 token 改為 write-only 引用，檢查日誌、錯誤和工具返回能否洩露原值。

注意點

這是 E2B 平臺控制的秘密引用，不等於通用的物件能力模型。

04Qwen Code中國 / 全球開發者2026-08-20 釋出 / 2026-08-21 觀察官方釋出

Qwen Code 0.21.15 在恢復審查前先確認程式碼沒有變

發生了什麼：/review 與 CI 重試新增 --resume，但只有 PR head 未變化時才繼續中斷審查；新版也修復 /rewind 丟歷史、重複 tool-call ID，並儲存 Web Shell 附件。

為什麼值得關注：恢復不能只看 Agent 記憶，還要先確認現實世界沒有變化。

適合誰看：使用 AI 做 PR 審查、CI 修復或長時間程式碼任務的維護者。

試試看

中斷審查後修改 PR head，再嘗試 --resume，確認系統會拒絕複用過期結論。

注意點

PR head 只覆蓋程式碼版本，不證明工作區、依賴和外部操作都未變化。

OpenViking 用可瀏覽檔案系統管理記憶、資料和 Skills

注意點

主專案使用 AGPLv3；官方 benchmark 不應直接外推到所有模型與任務。

06Tencent Zhuque Lab AI-Infra-Guard中國 / 全球開源2026-08-17 釋出 / 2026-08-21 觀察官方倉庫

騰訊 AI-Infra-Guard 把 Agent、MCP 和 Skills 放進同一套掃描工具

發生了什麼：騰訊朱雀實驗室的開源紅隊平臺同時覆蓋 OpenClaw、Agent 工作流、MCP Server、Skills、基礎設施 CVE 與越獄評估；v4.5.2 增加多項繞過和工具白名單檢測。

為什麼值得關注：Skills 與 MCP 正成為 Agent 的軟體供應鏈，卻常常缺少安裝前檢查。

適合誰看：會安裝第三方 Skills、MCP 服務或管理企業 Agent 工具鏈的人。

試試看

先用 aig-skill-scan 掃描一個準備安裝的 Skill，再按 T01-T09 風險分類人工複核。

注意點

掃描仍需人工確認；專案當前無認證機制，只適合本機或內網部署。

07oMLX全球開源 / Apple Silicon2026-08-21 觀察官方倉庫

oMLX 讓 Mac 本地模型擁有 RAM 與 SSD 兩層 KV 快取

發生了什麼：oMLX 為 Apple Silicon 提供連續批處理、多模型管理、OpenAI/Anthropic 相容 API，以及熱 RAM、冷 SSD 兩層 KV cache；服務重啟後仍可複用匹配字首。

為什麼值得關注：把快取延伸到 SSD，可減少本地長上下文反覆預填充的等待。

適合誰看：希望在 M 系列 Mac 本地執行程式設計模型、VLM 或 embedding 的團隊。

試試看

開啟 SSD cache，比較同一長字首的首次與二次請求，並記錄真實命中率。

注意點

效能會隨機型、模型、量化和命中率變化，官方數字不能直接當成本機預期。

08NVIDIA Confidential Containers美國 / 全球資料中心2026-08-11 釋出 / 2026-08-21 觀察官方文件

NVIDIA 機密容器 1.1 支援 HGX B300 多 GPU 工作負載

發生了什麼：Confidential Containers 1.1.0 新增 HGX B300 單、多 GPU passthrough，支援 Ubuntu 26.04、Kata Containers 4.0.0、containerd 2.3.x，並擴大 OpenShift GA 覆蓋。

為什麼值得關注：敏感 AI 工作負載的“計算中保護”正走向新一代多 GPU 系統。

適合誰看：執行金融、醫療、主權 AI 或模型 IP 保護工作負載的平臺團隊。

試試看

先核對官方限制：主機 GPU 均需啟用機密計算，多 GPU 必須分配給同一臺機密 VM。

注意點

這是特定元件組合的參考架構，不代表任意 Kubernetes 與 GPU 環境都獲同等保障。

市場觀察：AI 競爭正從模型能力延伸到任務恢復、上下文治理、本地速度和敏感負載保護。執行環境與工作流體驗正在成為新的產品分水嶺。
