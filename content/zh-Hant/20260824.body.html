RISC機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它還要持續行動、扛住故障、抵禦越權，並進入真實組織協作。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體持久執行、容錯、恢復與水平擴充套件。身體站不住，一次故障就會把工作清空。
I｜智慧 / 大腦模型迴圈、記憶、工具與編排。它決定 Agent 如何思考、呼叫和完成複雜工作。
S｜安全 / 免疫能力物件、策略審批、回滾與審計。沒有免疫，恢復與連線會擴大失控半徑。
C｜連線 / 社會跨公司授權、中立基底、會話型別與生態連線。沒有社會介面，Agent 只能停在單一產品裡。

01Cline CLI美國 / 全球開發者2026-08-23 釋出 / 2026-08-24 觀察官方釋出

Cline CLI 讓 Hub 升級先排空任務再恢復會話

發生了什麼：Cline CLI 3.0.57 新增 hub drain 與 upgrade：先停止接收新的變更任務，等在途工作結束後再重啟；客戶端重連時按事件 ID 補放斷線期間的事件並去重，同時修復自定義 OpenAI 相容模型被錯誤關閉工具呼叫的問題。

為什麼值得關注：安全升級不只是重啟服務，還要明確何時停止接單、怎樣收尾在途工作，以及重連後如何避免漏事件或重複執行。

適合誰看：維護長駐程式設計 Agent、共享 Hub 與自定義模型閘道器的團隊。

試試看

在測試 Hub 發起長任務後執行 drain，確認新寫操作被拒絕、舊任務完成；升級重連後再核對事件是否只出現一次。

注意點

會話與事件恢復不等於外部副作用已經冪等；版本說明也沒有證明跨節點故障切換或動作回滾。

02Qwen Code中國 / 全球開源2026-08-23 釋出 / 2026-08-24 觀察官方預釋出

Qwen Code 新增事件回放審查與修復測試見證

發生了什麼：Qwen Code 8 月 23 日 nightly 在 0.22 穩定版之後加入 temporal-reachability 與 incident-replay 兩種審查視角，要求每項修復說明對應測試並裁決不收斂；守護程序會話恢復上次選擇的模型，Goal 也開始記錄 token 消耗。

為什麼值得關注：程式碼審查開始從靜態挑錯走向事件路徑、復現證據和修復驗證，恢復會話時連模型選擇與成本狀態也要一起回來。

適合誰看：使用 Qwen Code、自動評審、後臺會話或成本治理的開發團隊。

試試看

對一個歷史缺陷啟用 incident-replay，要求修復項附帶測試；重啟守護程序後檢查模型選擇與 Goal token 記錄。

注意點

這是 nightly；新審查視角能提高可解釋性，但不能替代人工複核，也不證明測試已經覆蓋真實生產事故。

03Ollama美國 / 全球本地 AI2026-08-23 釋出 / 2026-08-24 觀察官方預釋出

Ollama 讓被取消的長預填充從可信快取點續跑

發生了什麼：Ollama 0.33 rc2 為 Claude Desktop 增加模型開關和應用整合檢視，並重做預填充恢復：長預填充被取消後保留已越過的恢復點，重試可從中途繼續；系統也不再記錄覆蓋範圍不實的恢復點，避免接近完成的請求從零重算。

為什麼值得關注：本地長上下文推理的體驗不只取決於速度；取消、重試和快取證據是否一致，直接決定時間、能耗與互動連續性。

適合誰看：執行本地模型、Claude Desktop、長上下文與 MLX 工作負載的使用者。

試試看

用長提示觸發預填充後主動取消，再以同一字首重試，比較恢復耗時、快取命中與輸出一致性。

注意點

這是釋出候選版；可信恢復點針對預填充快取，不等於 Agent 工具動作、會話狀態或外部結果能夠回滾。

04LiteLLM美國 / 全球基礎設施2026-08-23 釋出 / 2026-08-24 觀察官方釋出

LiteLLM 1.98 把 MCP 資源繫結與長流存活寫進閘道器

發生了什麼：LiteLLM 1.98 為 MCP 客戶端請求增加讀取超時，並讓 Gateway bearer token 繫結 RFC 8707 resource；同時加入 SSE 心跳、每部署失敗策略、虛擬路由模型，以及 session_id 與 trace_id 日誌關聯，映象提供 Cosign 簽名。

為什麼值得關注：模型閘道器正在承擔 Agent 連線層職責：令牌要繫結資源，長流要能存活，故障與費用也要落回具體部署和會話。

適合誰看：管理模型路由、MCP 閘道器、長流請求、審計與成本的團隊。

試試看

給一個 MCP Gateway 配置資源限定 token 和讀取超時，再模擬長 SSE 流與部署失敗，核對路由、心跳和 trace 關聯。

注意點

功能很多且跨模組，升級前應逐項迴歸；資源繫結與簽名映象也不能自動證明下游工具或策略配置安全。

05Deep Agents Code美國 / 全球開源2026-08-23 釋出 / 2026-08-24 觀察官方釋出

Deep Agents Code 同時收緊環境變數與自動審批邊界

發生了什麼：Deep Agents Code 0.1.60 新增可編輯 trace 後設資料、命令高亮和統一通知中心，並允許配置專案 .env 載入；安全修復會阻止 dotenv 注入 Git 配置鍵，Auto 審批模式則可以跨會話保持，同時修正進行中 trace 訊息識別。

為什麼值得關注：開發 Agent 的配置、審批與追蹤不是三個孤立開關；一旦跨會話儲存，它們就共同決定下一次啟動能讀什麼、做什麼。

適合誰看：使用 Deep Agents、專案級環境變數、自動審批和追蹤系統的開發者。

試試看

在隔離倉庫配置 .env 與 Auto 審批，重啟會話後檢查審批是否保留，並驗證 Git 配置注入鍵被拒絕。

注意點

dotenv 拒絕名單在專案威脅模型中仍被標註為盡力而為；跨會話審批也需要團隊自行設定合理預設值。

06Agno美國 / 全球開源2026-08-23 釋出 / 2026-08-24 觀察官方 Alpha 釋出

Agno 3.0 alpha 把工作區排除規則變成訪問邊界

發生了什麼：Agno 3.0.0a4 讓 SQLite 預設使用 WAL 日誌模式，並把此前未真正執行的資料庫測試門禁納入 CI；Workspace exclude_patterns 現在會被強制執行為訪問邊界，同時新增 MiniMax 影片生成工具，並將遙測呼叫改為非同步觸發。

為什麼值得關注：Agent 框架進入大版本前，最有價值的變化往往不是新工具，而是資料庫門禁真的執行、排除規則真的阻止訪問。

適合誰看：評估 Agno 3.0、工作區隔離、SQLite 持久化與多媒體工具的團隊。

試試看

在測試工作區排除一個目錄並嘗試讓 Agent 讀取；同時製造併發 SQLite 寫入，觀察 WAL 與 CI 資料庫套件。

注意點

這是 alpha 版本，介面和行為可能繼續變化；排除規則只覆蓋框架識別的工作區路徑，不等於系統級沙箱。

07CUA-Lite全球開源2026-08-23 釋出 / 2026-08-24 觀察官方新倉庫

CUA-Lite 統一桌面、瀏覽器與手機 Agent 的訓練和評測

發生了什麼：新開源的 CUA-Lite 用一套 schema、介面和命令統一桌面、瀏覽器與移動端 Computer-Use Agent，內建 10 多種 Agent、30,000 多個可驗證任務，並把 SFT 資料、基準評測、沙箱與強化學習環境接進同一框架。

為什麼值得關注：計算機操作 Agent 長期缺少可交換的軌跡與環境介面；統一格式能減少每換模型、裝置或基準就重寫適配層的成本。

適合誰看：訓練、評測或部署桌面、網頁和移動端操作 Agent 的團隊。

試試看

先用 lite.demo 跑一條軌跡，再把同一 Agent 換到 WebArena 或 AndroidWorld，核對動作、觀測和結果記錄格式。

注意點

README 中的 Agent 數量與任務規模是專案宣告；不同環境仍需各自安裝，基準可復現性也要獨立核驗。

08原始碼精讀方法論 Skill中國 / 全球 Skills2026-08-23 釋出 / 2026-08-24 觀察官方新倉庫

一箇中文 Skill 要求每條原始碼判斷都能跳回具體行

發生了什麼：新專案 source-reading-methodology 將大型倉庫精讀拆成語料準備、大綱、章節書稿和成書四階段，要求先鎖 commit，再為程式碼論斷記錄真實檔案與行號，並在批次寫作前建立逐位元組校驗器；它可安裝到 Cursor、Claude Code 或通用 Skills 目錄。

為什麼值得關注：這把“讓 AI 讀原始碼”從一次聊天變成可複查的出版流程：模型的解釋必須繫結版本、路徑、行號和機器校驗。

適合誰看：做原始碼研究、技術課程、程式碼審計、文件出版或 Agent Skills 的讀者。

試試看

挑一個小模組，先鎖定 commit 並建立行號校驗，再讓 Skill 只寫一節；隨機抽三條論斷回到原始碼核對。

注意點

專案展示的課程與引用數量來自作者案例，不能直接外推到所有倉庫；嚴格流程也會顯著增加前期準備成本。

09Ray美國 / 全球架構2026-08-23 釋出 / 2026-08-24 觀察官方釋出

Ray 2.58 把快取感知路由、gVisor 沙箱與 TPU 排程放進同一底座

發生了什麼：Ray 2.58 完成 KV cache 與 token 感知請求路由：入口程序完成分詞並廣播快取生命週期，CPU 解除安裝塊也計入命中；同時新增實驗性 gVisor Ray Sandbox、TPU 子切片群排程，並將任務事件移出 GCS 熱路徑。

為什麼值得關注：分散式 AI 底座正把推理效率、隔離、硬體排程和觀測解耦同時推進，避免所有壓力都集中到單一控制面。

適合誰看：執行分散式推理、Ray Serve、TPU 叢集、沙箱任務和觀測平臺的團隊。

試試看

在測試叢集啟用 KV 感知路由和 Ray Sandbox，比較快取命中、重複分詞、隔離效果與 GCS 事件負載。

注意點

Ray Sandbox 仍是實驗功能；快取路由依賴特定 LLM 棧，TPU 與事件新路徑也需按叢集版本分別驗證。

架構觀察：今天最清楚的變化，是“恢復成功”正在被重新定義：快取命中、會話重連或程序重啟只是起點，狀態來源、許可權邊界、事件序列、外部效果和執行環境必須能彼此印證。
