RISC 機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它要能持續執行，要能判斷和行動，要能抵禦錯誤、攻擊和投毒，也要能進入真實世界的協作網路。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體容錯、持久執行、故障切換、水平擴充套件。沒有強韌機體，一次崩潰就會帶走全部工作。
I｜智慧 / 大腦推理迴圈、記憶、工具呼叫、任務編排。這是今天所有 Agent 框架最擁擠、也最成熟的競爭層。
S｜安全 / 免疫物件能力、策略約束、回滾機制、審計鏈路。沒有安全免疫，一條被投毒的指令就可能造成真實損害。
C｜連線 / 社會跨公司授權、中立基底、會話型別、協作邊界。沒有連線網路，每家公司的 Agent 都只能困在自己的孤島裡。

01Dify中國/全球開源2026-07-17 / 2026-07-20 觀察官方釋出

Dify 1.16.0 推出 Linux 沙箱 Agent，卻把“僅限可信使用者”寫進發布警告

發生了什麼：Dify Agent Beta 提供視覺化構建器、Linux 沙箱、Skills、檔案、工具和知識連線，並明確警告服務只能提供給可信、非惡意使用者。

對 ALUX 的關係：這條警告說明上層產品已經能把模型送進真實執行環境，卻還不能把惡意使用者、技能來源和工具許可權穩定收進同一責任邊界。ALUX 可承接沙箱外層的能力合同、策略裁決和效果收據。

可行動建議與產出物：建議形成 Untrusted Agent Execution Contract，繫結 tenant trust、sandbox profile、skill provenance、tool grant、network policy、effect receipt 與 revoke event。 可沉澱為：Untrusted Agent Execution Contract v0。

RISC：S 主 · 安全 / 免疫C 輔 · 連線 / 社會

這條訊息主要動到機器人的安全/免疫：產品明確承認惡意使用者可能穿透現有邊界；連線/社會為次維度，因為 Skills、工具和知識入口把風險擴充套件到整個生態。

隔離邊界部分Agent 在 Linux 沙箱中執行，但官方仍限定只服務可信使用者。
策略審批部分構建器可連線 Skills、檔案、工具與知識，但釋出說明未給出統一風險審批矩陣。
合作/學習視窗

Dify 可作為 ALUX 的上層編排與生態入口，ALUX 為每個沙箱、技能和工具呼叫提供不可降級的能力與執行證據。 學習 Agent builder、沙箱配置、Skills 與生態工具如何組合成低門檻產品面。

風險邊界

Beta 與可信使用者警告都意味著安全邊界尚未成熟；Linux 沙箱本身不等於物件能力、惡意租戶隔離或外部效果回滾。

今天的新變化

1.16.0 首次推出 Dify Agent Beta，並把可信使用者限制與 Linux 沙箱能力放在同一份官方釋出說明中。

02Strands Agents美國/全球開源2026-07-17 / 2026-07-20 觀察官方釋出

Strands Harness 1.10 同時加入統一儲存與干預治理，狀態和人工介入開始共用執行面

對 ALUX 的關係：持久狀態、上下文解除安裝、人工干預和觀測欄位不再是四套外圍功能，而是一次 Agent 執行的連續責任鏈。ALUX 應把狀態名稱空間、干預者、策略依據和恢復遊標納入長交易。

RISC：R 主 · 強韌 / 機體S 輔 · 安全 / 免疫

這條訊息主要動到機器人的強韌/機體：統一儲存與上下文解除安裝決定執行能否延續和恢復；安全/免疫為次維度，因為干預必須留下策略與責任證據。

持久執行是統一儲存介面與 offloader 名稱空間把執行狀態提升為正式能力。

合作/學習視窗

可為 Strands 儲存與 intervention handler 提供 ALUX adapter，將干預前後狀態和能力變化寫入可重放記錄。 學習統一儲存與干預 handler 如何進入 harness 層，而不是停留在業務回撥。

風險邊界

社群治理包不等於強制執行；減少 trace 屬性也可能削弱調查證據，需區分隱私最小化和審計缺口。

1.10.0 首次把統一儲存、自動名稱空間與 intervention governance 放進同一版本。

03Anthropic Claude Code美國/全球2026-07-19 / 2026-07-20 觀察官方釋出

Claude Code 2.1.215 停止自動執行 verify 與 code-review，驗證責任被改回顯式呼叫

發生了什麼：Claude Code 不再自行觸發 /verify 與 /code-review；使用者需要顯式呼叫這兩個技能。

對 ALUX 的關係：這不是簡單的互動調整，而是驗證責任的遷移：系統從預設自動檢查改為由操作者宣告何時驗證。ALUX 應記錄驗證觸發者、策略依據、覆蓋範圍與缺席原因，避免“沒呼叫”被誤讀成“已透過”。

可行動建議與產出物：建議形成 Verification Invocation Receipt，記錄 initiator、policy trigger、scope、tool version、result 與 skipped reason。 可沉澱為：Verification Invocation Receipt v0。

RISC：S 主 · 安全 / 免疫I 輔 · 智慧 / 大腦

這條訊息主要動到機器人的安全/免疫：驗證與程式碼審查是否發生，直接影響錯誤能否進入真實系統；智慧/大腦為次維度，因為 Agent 不再自動決定檢查時機。

策略審批部分驗證改為顯式命令，但官方未說明哪些風險必須強制觸發。
回滾審計部分verify 與 code-review 是證據入口，但版本未描述失敗後的回滾狀態。
合作/學習視窗

可把 Claude Code 的顯式驗證命令對映為 ALUX 長交易中的 policy gate 與 completion evidence。 學習編碼 Agent 如何區分生成、驗證和審查三個獨立狀態。

風險邊界

釋出說明只有一條行為變更，沒有說明為何撤回自動觸發，也沒有證明顯式呼叫能覆蓋所有關鍵變更。

今天的新變化

2.1.215 明確撤回自動執行 verify 與 code-review 的行為，把驗證觸發責任交回顯式命令。

這條訊息主要動到機器人的安全/免疫：過濾錯誤和追蹤資料最小化決定敏感內容如何被阻斷與記錄；智慧/大腦為次維度，因為模型解析 hook 改變實際使用的大腦。

風險邊界

hook 名稱中的 capability 不等於物件能力；省略請求引數保護隱私的同時也可能減少事後復現資訊。

今天的新變化

2.13.0 首次把內容過濾顯式錯誤、Agent 模型解析 hook 與請求引數追蹤開關組合釋出。

最直接視窗：Dify、Strands、Pydantic AI 與 Anthropic SDK 都適合作為上層 adapter 樣本；MCP Inspector 可承擔協議會話驗收，Claude Code 可用於驗證觸發與完成證據演示。
融資敘事視窗：今天沒有新的可靠融資金額進入正文。更強的資本敘事是：產品開始為可信租戶、狀態恢復、人工干預、協議會話和秘密處理投入同一輪工程預算，說明生產級完整機器的缺口正在被行業共同確認。

技術 / 產品啟發

優先 Demo：讓 Dify Agent 透過 MCP Tunnel 呼叫外部 Skill，在 Strands 儲存中保留檢查點；觸發內容過濾和人工干預後，展示 ALUX 如何凍結能力、記錄驗證責任、脫敏秘密並從同一長交易恢復。

風險邊界

ALUX 不能被說成已經完整交付智慧體平臺。當前底層 TVM 已具備併發、持久化執行、能力安全、執行記錄和逐位元重放審計等關鍵基礎；智慧體產品層、可觀測性、儀表盤、追蹤與評估工具仍是待構建和融資重點。也不要說 TVM 讓 LLM 本身確定性。準確說，TVM 記錄模型輸出和執行環境輸入，使編排、許可權、狀態轉移和審計可重放、可驗證。Linux 沙箱、顯式驗證、統一儲存、干預 handler、內容過濾、MCP Inspector 與 Tunnel，都不能自動證明物件能力、跨步驟原子回滾或中立跨公司協作。
