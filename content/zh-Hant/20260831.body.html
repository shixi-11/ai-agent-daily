RISC機器說明

RISC = 生產級 Agent / 機器人身體的四個系統

一個真正能上生產的 Agent，不能只有大腦。它還要持續行動、扛住故障、抵禦越權，並進入真實組織協作。

行業已經交付了一顆出色的大腦，但生產級 Agent 還需要機體、免疫和社會。ALUX 構建的，就是這臺完整機器。
R｜強韌 / 機體持久執行、容錯、恢復與水平擴充套件。身體站不住，一次故障就會把工作清空。
I｜智慧 / 大腦模型迴圈、記憶、工具與編排。它決定 Agent 如何思考、呼叫和完成複雜工作。
S｜安全 / 免疫能力物件、策略審批、回滾與審計。沒有免疫，恢復與連線會擴大失控半徑。
C｜連線 / 社會跨公司授權、中立基底、會話型別與生態連線。沒有社會介面，Agent 只能停在單一產品裡。

01DeepSeek Harness中國 / 全球 Agent 開發者2026-08-30 釋出 / 2026-08-31 觀察官方開源釋出

DeepSeek Harness 把重連與計劃放進會話控制面

發生了什麼：DeepSeek Harness 0.1.2-alpha.2 在介面顯示連線失敗，支援自動重試與立即重連，並在會話標題展示活動定時計劃。版本還把外掛按會話與全域性作用域分組，補充 Agent Preset 切換、長會話處理和 RemoteError 統一封裝。

為什麼值得關注：長時 Agent 不能把斷線當成無聲失敗；計劃、重試、作用域和錯誤物件需要在同一控制面裡可見。

適合誰看：部署 DeepSeek Harness、遠端閘道器或定時 Agent 會話的團隊。

試試看

建立一個短週期測試計劃，主動中斷遠端連線，核對狀態提示、自動重試、立即重連和計劃是否只執行一次。

注意點

該版本仍是 alpha；自動重連不等於任務冪等，活動計劃可見也不證明跨程序恢復與副作用補償已經完成。

02Amazon SageMaker Feature Store美國 / 全球機器學習平臺2026-08-28 釋出 / 2026-08-31 觀察官方釋出

SageMaker Feature Store 補上批寫與記錄發現

發生了什麼：AWS 為 SageMaker Feature Store 新增 BatchWriteRecord 和 ListRecords：單次請求可跨多個特徵組寫入最多 25 條記錄，逐條返回失敗與未處理項並保留 EventTime 排序；後者可分頁列舉標準與記憶體儲存層的記錄 ID。

為什麼值得關注：批次寫入降低連線開銷，記錄列舉則讓只存在記憶體層的資料重新具備發現與修復入口。

適合誰看：維護實時特徵、風控流、推薦系統和記憶體型線上儲存的團隊。

試試看

用測試特徵組混合成功、校驗失敗和節流記錄，只重試 Errors 與 UnprocessedEntries，再核對 EventTime 順序。

注意點

單批上限為 25 條且採用部分成功語義；呼叫方仍要自己做退避、冪等與失敗分類，不能把一次響應當成原子事務。

03OpenAI Agents SDK美國 / 全球開發者2026-08-19 釋出 / 2026-08-31 觀察官方開源釋出GitHub Stars 29,077許可證 MIT

OpenAI Agents 0.22 清理被攔截的工具結果

發生了什麼：OpenAI Agents Python 0.22 會把被輸出護欄拒絕的終止型工具結果，從可回放與持久化 SDK 狀態中刪除；非流式 Responses 返回 failed 或 incomplete 時直接拋錯，並隔離獨立 RunState 檢查點的用量統計。

為什麼值得關注：安全拒絕若仍殘留在回放狀態，後續恢復可能重新暴露被攔內容；計量串線也會汙染成本判斷。

適合誰看：使用 Agents SDK、輸出護欄、檢查點與多 Agent 用量統計的團隊。

試試看

讓測試工具返回一段應被護欄拒絕的虛構資料，儲存並恢復 RunState，確認持久狀態、追蹤與用量都符合預期。

注意點

版本調整了顯式 OpenAI 客戶端的配置合同；升級前要遷移 organization 與 project 引數，並檢查自定義持久層。

04ONNX Runtime WebGPU Plugin EP美國 / 全球瀏覽器推理2026-08-24 釋出 / 2026-08-31 觀察官方開源釋出GitHub Stars 21,680許可證 MIT

ONNX Runtime WebGPU 0.3 擴大瀏覽器生成模型邊界

發生了什麼：ONNX Runtime WebGPU Plugin EP 0.3 新增初步 PagedAttention、量化 KV 快取、滑窗 GQA 與更多運算元和整數型別，加入冷啟動並行著色器編譯、Intel FP16 核心、魯棒性選項及離線圖轉換的無裝置編譯會話。

為什麼值得關注：瀏覽器推理正從小模型演示進入生成模型執行時，快取正確性、冷啟動和裝置差異開始成為一等問題。

適合誰看：開發 WebGPU 推理、瀏覽器 Agent、本地隱私應用和跨裝置模型體驗的團隊。

試試看

用同一模型分別測冷啟動、批次預填充和解碼，記錄著色器編譯、KV 快取、輸出一致性與不同瀏覽器的降級路徑。

注意點

PagedAttention 仍是初步支援，硬體與瀏覽器實現差異很大；釋出說明由 AI 輔助起草，關鍵路徑應回看 PR 與測試。

05Google TIPS v1美國 / 全球視覺研究2026-08-19 釋出 / 2026-08-31 觀察官方開放權重

Google 開放 TIPS v1 空間視覺權重

發生了什麼：Google 在 Hugging Face 釋出 TIPS v1 系列權重，覆蓋 S/14 到 1.1B 視覺引數的 g/14，並給出 Transformers 載入程式碼。模型同時輸出全域性影象嵌入與逐 patch 空間特徵，g/14 提供 448 和 224 兩種解析度。

為什麼值得關注：圖文模型若只保留全域性相似度，會丟掉物體位置與區域性關係；空間特徵為分割、檢索和視覺工具呼叫留下介面。

適合誰看：研究視覺檢索、零樣本分類、空間理解與多模態 Agent 的團隊。

試試看

載入 Apache-2.0 的 g/14 權重，對同一圖片比較 CLS 與 patch 特徵，再用簡單 PCA 檢查空間結構是否符合畫面。

注意點

這是 ICLR 2025 模型的官方轉換與開放權重，不是新論文；需要 trust_remote_code，使用前應審查自定義程式碼與視訊記憶體需求。

06Hugging Face Open ASR Leaderboard印度 / 全球語音研究2026-08-28 釋出 / 2026-08-31 觀察官方研究釋出

Open ASR Leaderboard 首次納入南方語言人群差異

發生了什麼：Voice Arena 與 Hugging Face 為 Open ASR Leaderboard 增加 Monsoon en-IN 和 hi-IN。四個 split 互不共享說話者，覆蓋 4,888 人並記錄 12 項屬性；Hindi 參考文字用 lattice 接納多種正字寫法。

為什麼值得關注：平均詞錯率會掩蓋地域、年齡、性別、裝置與口音差異；公開加私有劃分也能降低針對榜單過擬合。

適合誰看：訓練語音識別、呼叫中心、語音 Agent 與多語言評測的團隊。

試試看

先在公開 split 自測，再按地區、裝置與性別拆分誤差；若提交榜單，把私有 split 只用於最終驗證。

注意點

資料小時數不大，價值主要來自說話者廣度；12 項人口屬性涉及敏感分析，使用時應遵守許可、隱私與公平性邊界。

07PONS Legal AI on Azure歐洲 / 受監管企業 AI2026-08-27 釋出 / 2026-08-31 觀察官方架構案例

PONS 把公共法律知識與客戶檔案分層

發生了什麼：Microsoft 公開 PONS 法律 AI 的三項架構取捨：持續整理公共法律資料的 Data Factory 與客戶檔案分離，AI Engine 透過佇列非同步取活並對失敗輸出自動重跑；資料駐留歐盟區域，服務間連線使用託管身份。

為什麼值得關注：受監管場景的可信度來自資料邊界、來源引用、失敗門禁和身份控制，而不是把更多檔案直接塞給模型。

適合誰看：建設法律、金融、醫療等受監管企業 AI 平臺的產品與架構團隊。

試試看

畫出公共知識、客戶私有資料、佇列、模型與審計日誌的資料流，逐條標出駐留、身份、引用和失敗重跑邊界。

注意點

這是 Microsoft 與 PONS 的案例口徑，不是獨立審計；合規認證、加密與拒答設計仍需結合合同和真實控制證據驗證。

本期觀察：AI 工程的下一步不是繼續把能力塞進同一個盒子，而是給失敗、狀態、人口差異和私有資料分別劃出可驗證的邊界。
