# Agent Daily 持续改进计划

起始日：2026-09-21。每日下午复盘当天真实结果，每次推进一个可验收的小改动。先稳定每日交付，再提高新闻覆盖和阅读体验；不另建正文发布任务。

## 不变的产品规则

- 首页是全部期刊的汇总入口，每一期保留独立的中英文日期地址。latest 可以移动，日期页不能指向 latest 或被下一期正文覆盖。
- 从现在开始逐期积累。既有历史原样保留，暂不补做缺期、不批量重写旧稿。
- 每天08:00启动主任务，Astra low、无fallback；独立英文审校、正式部署验收及通知去重保持。
- 只保留中 / EN；采集器只能提供候选，不得自动改写正文或发布。
- 每天目标12–18条、5–7条详读、至少3条有趣发现；普通开发工具维护更新最多2条。质量不足时说明缺口，不为凑数放入旧闻。

## 已确认的抓取缺口

GitHub采集器当前有22个固定仓库、10个Hugging Face组织、29个RSS入口，仍偏开发工具；不少固定仓库对应旧代模型。fetch没有显式超时/重试，主要串行抓取；单源错误留在JSON后进程仍能成功退出，且缺少整体健康指标。第三方Anthropic RSS被标为official，应纠正来源等级。

云端采集目标为北京时间07:20、13:20、17:20、21:20。主任务在模型启动前下载最近成功 artifact，校验当日日期、逐源健康和180分钟新鲜度，再生成只含候选线索的标准快照；没有当日云端结果时主动触发一次 Actions 并最多等待150秒，仍失败才进行一次有界本地补抓。编辑须回到官方原文核验，并在 sources.json 记录快照实际贡献。2026-09-25 的07:20定时未产生当日 artifact，08:00本地补抓又因12个来源失败及候选ID碰撞而没有进入编辑；正文依靠独立原文研究完成。修复提交上的真实 Actions `36116466087` 16秒完成，61源无必选失败，得到437条候选且437个ID均唯一，验证了云端测试、采集、上传、下载、校验和标准化链路；因发生在正文发布后，不计作当天选题贡献。首次主任务实际消费仍待下一期验证。

本地抓取已经有代理适配、三次有限重试、同日两小时缓存；但默认validate为空操作，不能仅凭HTTP成功就认定拿到有效新闻正文。

## 每日推进与七期复盘

每日17:00检查实际交付与来源质量，先处理当日阻塞，否则选择最高优先级未完成项。一次只交付一个有测试/真实证据的小改动，更新本计划并同步GitHub。不要为改进任务另发日报或重复Telegram通知。

从9月21日起累计七期，记录：正式发布和通知结果、耗时、各阶段失败、必查厂商覆盖、来源抓取健康、重大漏报样本、重复事件、趣味发现数量与修正次数。目标为七期各有固定中英日期页、零覆盖/零重复通知、失败不冒充无消息、已核实重大模型发布有明确入选或排除依据。覆盖率针对已定义观察清单，不声称全网零漏报。

收到实质进展、明确回归或需要用户处理的阻塞再通知；无变化保持安静。故障或抓取限制如实记录，不能调低门槛伪造成功。过去期刊的修订、补发和回填不在本计划自动执行范围。
