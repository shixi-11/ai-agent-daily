# ALUX AI智能体情报日报风格规范

## 刊物定位

这是一份面向大众技术读者的全球 AI 每日情报。它从大厂新功能、AI Agent、GitHub 开源、Skills、软硬件、系统架构和市场变化中，挑出真正好玩、有用、有意义的信号。

ALUX 是本刊品牌和 RISC 方法来源，但每条新闻不再强制映射 ALUX。读者首先应看懂“发生了什么、为什么值得关注、可以怎么用”。

## 编辑原则

- 以官方发布、官方 GitHub、官方技术博客、可验证论文和可靠商业来源为主。
- 标题写清真正的变化，不用空泛趋势词，不把完整语义拆成奇怪短句。
- `AI Agent雷达` 卡片标题使用“具体主体 + 具体变化”，中文视觉宽度最多 20 个中文字量；删掉“开始把……同时……交出来”这类口语脚手架，并检查 1440、1024、390 宽度的实际断行。
- 大项目与小项目一视同仁：新鲜度、使用价值和趋势信号比品牌大小更重要。
- 每条重点信号回答：发生了什么；为什么值得关注；适合谁看。实用补充只保留“试试看”和“注意点”两项。
- 不强制写“对 ALUX 的关系”或“ALUX 动作”。ALUX 只在经过真实分析、具有特殊相关性时出现。
- 不设独立融资窗口。融资只在能解释技术路线、产业结构或全球市场变化时作为市场信号入选。
- 不把营销表述当成技术证明，不把 trace、log 或 system of record 直接写成可重放执行证据。
- 编辑过程只留在内部：公开页面不得出现“选题边界”“观察理由”“为什么入选”“本刊不会凑数”“宁可留白”等自我说明，也不向读者展示工作流、门禁或选稿辩解。

## 选题组合

- 每天目标 12-18 条独立消息，其中 5-7 条重点详报，其余为短讯；重大新闻多时可增加，材料不足必须先补查并记录具体原因，不拿旧闻凑数。普通开发工具版本更新合计最多 2 条，不受 category 标签影响。重要新模型（含闭源/API/开放权重）必须优先核查并入选；有趣发现目标至少 3 条，覆盖创作、游戏、生活应用、机器人或独立小项目。覆盖至少 4 种选题类别，不让整期退化成版本更新清单。
- 不再给产品、模型、软件设置合计 50% 上限；普通开发工具维护更新最多 2 条，重要新模型与有趣新应用优先。
- 每期至少有 2 条 `open-source` 或 `skill-tool`，并至少有 1 条 `hardware`、`architecture`、`research` 或真正有解释力的 `market` 信号。
- 产品与创作工具、模型与研究、开发者生态、软件与硬件、美国与中国及其他全球信号应形成自然组合；没有证据时不为配额制造条目。
- 大项目和小项目按读者价值、可试玩性、新鲜度、意外性与趋势含量判断，不按公司体量排序。
- 但大型 AI 厂商首次公开模型权重、完整代码、数据集或关键开源工具链时，必须先进入官方来源候选池并做明确取舍；经核验属于重要开放发布的，优先于普通版本更新。
- 编辑用词要区分 OSI 开源、开源代码、开放权重和自定义社区许可；权重可下载不等于 OSI 开源。
- 持续观察项没有官方状态变化时不占正文版面；一旦官方开放新的权重、模块或本地运行实现，按新变化报道，并与此前仅可通过 API 使用的能力分开说明。
- GitHub 开源与 Skill 推荐在成稿当天刷新 Stars。卡片元信息显示 `GitHub Stars 12,345` 和许可证状态；GitHub 未声明许可证时如实写 `许可证未声明`。板块写明“Stars为成稿时的关注度快照，不代表质量排名”，不能按 Stars 高低替代编辑判断。
- 所有卡片同时保留准确发布日期和本期观察日期；两周前的信息只有出现可核验的新版本、新证据或开放状态变化才可入选，不能伪装成当天发布。
- 每天监测 Codex 自动/全局额度重置实际发生的时间，以及重置卡实际发放的时间和范围。只有 OpenAI/Codex 官方、已确认 Codex 团队成员或 OpenAI Support 明确宣布的事件才能进入日报，并绑定确认事件 ID。帮助页释义、普通账户倒计时、单一账户截图、社区猜测、传言和无可靠来源推文只留内部；没有确认事件时正文完全不提，也不写机制说明。

## 每期固定结构

1. **Hero**：日期、主标题、lead、四项统计与“今日总判断”。lead 最多约 70 个中文字符，总判断最多约 100 个中文字符。四项统计依次表达“值得关注、可动手试、开源发现、覆盖区域”，不得用信号数和来源数重复凑数。右侧 `今日AI导航` 只做当期事实地图：每行一句事实和一句看点。
2. **RISC机器说明**：保留 `R｜强韧 / 机体`、`I｜智能 / 大脑`、`S｜安全 / 免疫`、`C｜连接 / 社会` 的固定前置说明。
3. **AI Agent雷达**：三张卡提炼跨信号判断，每张卡至少连接两条正文信号，最多两句话；不得重复 `今日AI导航` 的栏目计数或逐条摘要。
4. **值得关注的新功能**：模型、平台、AI Agent、软件与工具的实质更新。
5. **GitHub开源发现**：开源项目、Skills、MCP、工具库和值得试玩的小项目。
6. **全球技术与市场观察**：软件、硬件、架构、商业模式与产业趋势。
7. **来源**：与正文信号对应，保留原始链接与来源级别。

类别不设逐栏配额，由信号质量和整期多样性共同决定入选；这条判断只用于编辑过程，不写进公开成品。

## RISC 使用边界

RISC 是生产级 Agent /机器人身体的四系统说明，用于给读者一张理解 Agent 生产化的地图。

- 保留正式母版 `2026-08-26-editorial-v3.1` 中的 `RISC机器说明` DOM、位置和颜色。
- 不对单条新闻显示 RISC 主/辅维度、Yes/No/Partial 或子项评分。
- 不为了 RISC 叙事强行改写新闻的真实主题。

## 中文文风

- 自然、顺、有人味，但保持情报刊物的准确和节制。
- 一段只承担一个完整意思，不为节奏把正常语法拆成碎句。
- 标题优先按完整语义短语组织，避免逗号串起两个以上主干；正文长句先在编辑层拆开，不能依赖浏览器在任意字之间换行。
- 不允许一个汉字或标点独占标题、导语或新闻段落的末行；三端截图出现这种情况时先改写句子。
- 站名固定为 `ALUX AI智能体情报日报`。
- 标题固定写 `RISC机器说明`、`AI Agent雷达`。`AI Agent` 内部保留空格，与中文间不再添加 ASCII 空格。
- 不用 `/`、`｜` 硬拼标题，但在语义本来需要时可正常使用。
- 避免“赋能”、“颠覆”、“革命性”与无证据的“首个”、“全球领先”。
- 单条新闻建议控制为：发生了什么 80-140 字、为什么值得关注 40-80 字、适合谁看 20-45 字、试试看与注意点各 35-70 字；整卡以约 280-380 字为宜。数字是编辑节制线，不为凑字数扩写空话。

## 英文文风

- 使用美式英语 `en-US`，写成母语级 technology-intelligence publication，不保留中文句式。
- 英文标题通常使用 3-16 个单词，保持语法成分完整；避免让冠词、介词或连词悬在行末，也避免一个短词独占末行。
- 英文正文将中文复句拆成自然的短句和段落，优先清晰主谓关系；不保留中文逗号链，不为了和中文版逐句等长而牺牲英语节奏。
- 中英标题可以使用不同语序和句长，但事实、数字、产品名与证据边界必须一致。
- 翻译完整执行“分析 → 初译 → 独立审校 → 润色”，不得逐字直译或由初译者同一遍自证通过。
- 中英双版保持事实、数字、版本、章节和外链集一致。

## 视觉与响应式

- 日报唯一正式母版由 `templates/report-master.json` 指定，当前固定为 `content/zh/20260826_ALUX_AI智能体情报日报.html`，版本 `2026-08-26-editorial-v3.1`。不得再用“日期最新的一期”替代母版，避免逐日漂移。
- 新一期先复制正式母版的 CSS、类名、DOM 骨架、颜色、字体层级、边框、页面宽度、章节秩序与响应式断点，再替换全部日期、事实、标题、数字、链接、摘要和判断。不得复制旧内容，也不得自行创造新版式。
- 正式母版使用纸张灰白、深海军蓝、青绿与低饱和琥珀，不默认使用红色；新闻页必须标记 `data-layout-version="compact-v1"`。
- 页内顶栏使用本地 ALUX 黑色三角标，置于白色方底与细灰边框内；浏览器页签必须独立引用不透明白底的 `alux-favicon.png`，不得复用透明底黑标。CSS 白框只影响网页内部，不能代替 favicon 图片自身的白底像素。
- 首页三项归档统计的数值与说明必须作为一组上下居中；日期范围较长时仍保持左对齐，不得贴住卡片上沿留下失衡空白。
- `.signal` 不使用左右等高双栏；`.side` 是紧凑的两行底部信息区，只显示“试试看”和“注意点”。不得给 `.item` 或新闻卡设置固定 `min-height` 来制造齐高空白。
- 结尾洞察使用一个全宽信息框，不并排放置无实质内容的伴随框。
- 桌面双栏在平板和手机收为单栏。所有网格、英文专名和来源 URL 在 320 px 下也必须可读且无裁切。
- 1440、768、390 分别作为桌面、平板、手机代表视图。最新一期必须在三端展示明确的网格重排，而不是整页等比例缩小；统计列为 4/2/2，雷达列为 3/1/1，RISC 映射为 4/2/1，实用区为 2/2/1。
- 英文 `.heat-row` 在 `621px` 以上使用至少 `172px` 标签列，`620px` 及以下改为单列；`.panel-head` 在 `920px` 及以下上下排列。
- 必须运行 `scripts/render-check.cjs` 验证真实文字边界，不得用隐藏溢出、缩小字号或改写译文掩盖重叠。
- 必须运行 `scripts/verify-locale-copy.cjs YYYY-MM-DD`；标题与正文禁止使用 `<br>`、`&nbsp;` 或不可见字符针对单一屏宽硬修。
- 必须先运行 `node scripts/verify-report-master.cjs`，确认母版文件和样式指纹没有被历史修订或误操作改变。
